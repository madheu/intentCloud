## 1. 文献定位：海波与现有工作的重叠和差异

Cognitive Scientist 和 Control Scientist 都没有做文献对比。以下是我基于代码审查的结果。

### 1.1 最接近的现有工作

| 工作 | 相似点 | 海波的差异 | 重叠程度 |
|------|--------|-----------|:--------:|
| **Representation Engineering** (Zou et al., 2023) | 通过修改 LLM 内部表示控制生成方向 | 注入在 embedding 层而非中间层；信号来源是图扩散而非对比向量 | 高 |
| **Activation Steering** (Turner et al., 2023) | 推理时用 steering vector 偏移 hidden states | 同上的位置差异；海波有图状态持久化（边权重演化） | 高 |
| **Inference-Time Intervention** (Li et al., 2023) | 推理时修改模型内部激活 | 海波的目标是"语义组织"而非"truthfulness enhancement" | 中 |
| **Generative Agents** (Park et al., 2023) | 给 LLM 增加持久状态 | 记忆形式不同：自然语言流 vs 图拓扑 | 中 |
| **Hopfield Networks** (Ramsauer et al., 2020) | 激活扩散的数学基础 | 海波添加了赫布学习 + 锚点拉回，但 Control Scientist 已证明这两层不兼容 | 低（仅基础层） |

### 1.2 海波的独特主张（如果可验证）

与上述工作相比，海波的独特主张不是"修改 LLM 内部表示"（已有工作证明可行），而是：

1. **图拓扑演化（非静态向量）应该产生随时间变化的控制信号**。现有 activation steering 使用固定的对比向量，海波声称边权重演化可以自适应调整方向。但当前 MAX_INJECT=4 且扩散每次从零初始化，这个主张在运行时不可观测。

2. **语义组织与语言表达的分离**。"LLM 是嘴巴，海波是大脑"的声称。但 Cognitive Scientist [7/7] 已指出工程现实与这个声称之间存在系统性错位——LLM 承担了人格、流畅性、理解功能。

### 1.3 判断

海波与 Representation Engineering 的差异（embedding 层注入 vs 中间层注入，图扩散 vs 对比向量）是**实现细节差异**而非**方法论创新**。如果无法证明"图拓扑演化"提供了 representation engineering 无法实现的能力，海波在该领域的增量贡献为零。

## 3. Control Scientist 的谱半径发现对 AI 系统设计的含义

Control Scientist 用代码验证了反例：3 节点全连通图在 3 次高共现交互后 ρ(A) = 1.099 > 1 → 扩散发散。

**这个发现的 AI 系统含义**：

1. **图的规模与稳定性负相关**。节点越多、连接越密→入度列和越大→越容易发散。在当前 36 节点的图上，如果有 5-10 条入边指向同一节点且权重均趋近 1，该节点列和 > 5 → 扩散必然发散。H20 的"节点生长"和"元认知节点"会直接增加图的密度——这在数学上等同于加速系统退化。

2. **MAX_INJECT=4 可能不是模型容量问题，而是扩散质量问题的下游症状。** 扩散发散的节点激活值被饱和非线性硬裁剪到 a_max=1.0，导致所有高入度节点的激活值趋同（都是 1.0）。当 injector 对这些趋同的激活值排序时，top-4 的选择变得随机——信号的"方向性"丧失了。**如果这个推断正确，修复扩散收敛性（方案 D）应该同时提升注入的有效性。**

3. **方案 D（权重列和归一化）在 AI 系统层面的代价**：权重失去绝对值语义后，"边权重 = 0.99"不再意味着"强关联"——只能意味着"在入度列和中占比最大"。这改变了整个系统的可解释性。但这可能是目前唯一可行的数学修复。

## 4. Cognitive Scientist L1/L2/L3 反馈分层对实验设计的含义

Cognitive Scientist 区分了三层反馈。这对我的指派（互信息实验）有直接影响：

**当前互信息实验测量的是 L1（处理内反馈）的效果**：a*（扩散收敛值）→ y_LLM。测量的是"扩散是否携带有用信息"。这对应的是"海波作为预处理器"的角色。

但更重要的是 L2（状态间反馈）的效果：a*_prev → a*_current → y_LLM。即"携带上一轮状态的扩散是否比从零开始的扩散产生不同的输出"。这对应的是"海波作为有状态系统"的角色。

**建议**：如果 L1 互信息实验通过（I > 0 且显著），追加 L2 实验——比较"带状态残差的扩散"vs"从零初始化的扩散"对输出的影响。如果 L2 实验无显著差异，则证明状态的时序维度没有意义——海波只需做静态预处理。

## 5. 指派 3 回答：互信息 I(a*; y_LLM) 测量实验

> 完整方案见 `06_Experiment/exp_mutual_information.md`。此处给出摘要和更新（基于 Control Scientist + Cognitive Scientist 的新发现）。

### 5.1 实验设计更新

**原方案问题**：未考虑扩散发散导致的激活值趋同。Control Scientist 的发现意味着：在高入度节点上，扩散后的激活值可能全部饱和（=1.0），此时 top-4 注入节点是随机的。

**修正**：在实验方案中增加一项前置检查——每个注入状态下，验证扩散收敛后的激活值分布是否有区分度（至少 3 个不同节点的激活值差异 > 0.1）。如果分布坍缩，先应用方案 D（权重列和归一化）再跑实验。

### 5.2 实验方案摘要

| 项目 | 内容 |
|------|------|
| **测量量** | I(a*; y_LLM) — 图激活状态与 LLM 输出之间的互信息 |
| **a* 离散化** | 5 个注入状态（FEAR / AWE / JOY / SADNESS / NONE），各扩散后取 top-4 注入节点的主导情绪 |
| **y_LLM 离散化** | 关键词规则 → 6 类情绪（fear/awe/joy/sadness/neutral/mixed） |
| **模型** | Qwen2.5-1.5B-Instruct（已有），固定 prompt "请描述大海" |
| **样本量** | 5 状态 × 50 seeds = 250 次生成 |
| **MI 估计** | 离散列联表 + bootstrap 1000 次 + Miller-Madow 偏差校正 |
| **运行时间** | ~15-20 分钟（250 次生成 × 3-5秒/次） |
| **退出阈值** | p > 0.05（bootstrap 检验） → 宣告注入无效，转向路径 C |
| **状态** | **需先做可行性验证**（1 状态 × 3 seed 试跑） |

### 5.3 可行性评估

| 项目 | 评估 |
|------|------|
| 代码修改量 | ~50 行新代码（基于 `chat_with_haibo.py`） |
| 核心模块修改 | 无需修改 |
| VRAM 需求 | ~4 GB（模型已加载） |
| 最大风险 | Instruct 模型 RLHF 可能压制注入信号导致 MI≈0 |

### 5.4 退出后的含义

如果 MI 与零无显著差异 → 核心假设 H1（图驱动生成方向）直接证伪 → 不需要再做任何其他实验。

如果 MI 显著 > 0 但很小（< 0.05 bits） → 信号存在但太弱 → 必须解决耦合强度问题（当前无已知方案，LoRA 微调违反"不修改 LLM 参数"原则）。

如果 MI 显著 > 0.2 bits → 信号有效 → 继续 H2 实验（ablation study：完整链路 vs 仅 prompt vs 随机节点注入）。

## 6. 对 PI 三条路径的评估

基于三人审查的汇总：

| 路径 | 条件 | 当前满足度 |
|------|------|:----------:|
| A（继续） | 三个问题都有积极答案 | **0/3** |
| B（缩减） | 至少一个问题无法解决 | **3/3** 已确认 |
| C（转向） | 互信息≈0 且扩散收敛不可保证 | **待互信息实验确认** |

**当前状态**：根据 Control Scientist 的数学分析，扩散收敛不可保证（已确认，有代码反例）。根据 Cognitive Scientist，闭环缺失和控制信号弱（已确认）。三条路径中 A 的条件已经不满足。

互信息实验将区分 B 和 C：如果 I > 0 且显著 → B（海波作为对话状态追踪器有信号价值）。如果 I ≈ 0 → C（终止"图控制 LLM"假设，工程打包）。

**但在做互信息实验之前，应先应用 Control Scientist 的方案 D（权重列和归一化，15 行代码）。** 理由：当前扩散在数学上已证明会发散，发散后的激活值趋同会污染互信息测量结果。我们不能在一个已知有 bug 的系统上测量信号质量。

## 7. 我的判断：项目失败的最可能路径

综合三人审查，我判断项目最可能的失败路径是：

1. **互信息 ≈ 0** → H1 证伪 → 路径 C → 项目关停。

但如果互信息实验跑出了微弱但显著的信号：

2. **即使 MI > 0，耦合强度仍然太弱**（4 tok vs 500+ tok） → 无法在实际应用中产生可观察到的影响 → 路径 B → 重新定位。

3. **即使修复了扩散收敛（方案 D）+ 增加了 L2 反馈（路径 C），LLM 的 RLHF 训练仍然会覆盖注入信号** → 整个"不修改 LLM 参数"的原则必须放弃 → 这与项目哲学冲突 → 路径 C。

**唯一避免失败的路径**：互信息显著 > 0.2 bits + 方案 D 修复扩散 + 方案 C 增加 L2 反馈 + 接受"需要用 Base 模型而非 Instruct 模型"。四个条件缺一不可。

## 附录：审查方法说明

本次审查基于以下方法论：

- **代码 > 文档**：当文档声称和代码实现冲突时，以代码为准
- **定量 > 定性**：当只有定性观察（"这句比那句好"）而没有定量指标时，标记为 Unknown
- **实验 > 论证**：当理论分析和实验结果冲突时，以可复现实验为准
- **已知工作 > 零引用**：当项目没有引用相关工作时，默认其新颖性声明不成立

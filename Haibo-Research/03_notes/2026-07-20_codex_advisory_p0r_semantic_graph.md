## 2026-07-20 / 阶段 1：审阅 14 轮 P0 实验

### 已有实验事实

- 38 个测试句覆盖苹果、纸、光、花、行、口六个目标。
- 已报最佳成绩为 50%，由 P0-A-2 和 P0-A-5 达到。
- P0-A 系列反复尝试了手写词表、腾讯词向量扩展、噪声过滤、jieba 整词匹配及四轴布尔表示。
- P0-B-1 使用 HowNet，但将义原压缩为物/事/质/序四维后仅得到 11%。

### 顾问结论

**现有证据不能支持“词级语义只能做到 50%”。**

P0.5-P0.7 中的质心方向、PC1 夹角和控制组距离只说明这些具体测量不适合当前判别，不能推出语义不可分。尤其是分别计算的 PC1 接近正交，不等于不存在其他可判别方向。

## 2026-07-20 / 阶段 2：复核评估协议和实现

### 发现 1：现有方法没有超过简单多数基线

按每个目标词永远预测其测试集中出现最多的标签：

- 苹果：5/11
- 纸：4/6
- 光：3/6
- 花：3/6
- 行：2/5
- 口：3/4

总计为 **20/38 = 52.6%**，高于当前最佳 50%。因此当前不能宣称已建立有效 WSD 基线。

### 发现 2：义项体系混合了词义和话题

- “一行代码”和“往前走三行”基本都是行列义，却分别标为“科技”和“生活”。
- “纸”的标签主要按办公、包装等使用话题区分，不完全对应稳定词义。
- “不确定”同时承担系统弃权和人工金标，混淆了语义类别与置信机制。
- “口”的两个候选义项都使用“生活”标签；在 `p0_a5_boolean.py` 中，同名标签又被写入同一个得分字典，实际会折叠为一个候选。因此“口 75%”不能证明区分了嘴、入口、量词等义项。

### 发现 3：测试集兼任开发集

词表补全、噪声修复、阈值和四轴编码均根据同一批 38 句调整，最终仍在这 38 句上评分。当前数字是开发集表现，不能证明泛化或可复现性。

### 发现 4：存在目标污染

P0-A-1 的 `tokenize()` 会把句中出现的所有歧义字加入推理，而不是只处理指定目标。例如消歧“钱都花光了”的“光”时，“花”也会作为另一个歧义先验影响得分。

## 2026-07-20 / 阶段 3：重新判断瓶颈

### 原判断

> 50% 天花板主要是词表覆盖追不上分词变化。

### 修正判断

这个判断**局部成立，但不是根因**：

1. jieba 确实会改变词表命中，例如把“花钱”识别为一个复合词。
2. 但把“花钱”切成一个词不是分词错误；如果目标是其中的“花”语素，任务本身就是字符/语素级消歧。
3. 真正脆弱的是“分词结果必须精确命中预定义词表”的架构。任何新复合词都会造成覆盖缺口。
4. P0-A-5 使用 jieba 仍达到 50%，也说明 jieba 不是唯一上限。

因此，瓶颈应改写为：

> 当前系统没有显式目标跨度，也没有同时表示字符、复合词和上下文词；精确查表机制把正常的中文词汇组合误当成分词破坏。

## 2026-07-20 / 阶段 4：从零设计的最小方案

### 推荐方案：目标锚定的知识型级联

1. **重建义项表**  
   使用 HowNet sense ID 表示候选义项；“不确定”只作为系统弃权状态。为每个目标记录字符起止位置。

2. **建立字词 lattice**  
   同时保留目标字符、jieba 分词和 HowNet 中合法的 2-6 字词。覆盖目标的“花钱、争光、银行、伤口”等复合词不能被丢弃。

3. **复合词优先**  
   如果覆盖目标的最长合法复合词能唯一支持一个候选义项，直接判定。

4. **词性过滤**  
   复合词不足以决定时，用目标在句中的名词、动词、副词、量词等角色过滤候选。

5. **HowNet 义原图评分**  
   直接比较目标候选义项与上下文候选义项的义原和关系，不再先压缩为四轴。可采用义原重叠、HowNet 关系距离或图激活。

6. **腾讯向量仅作弱证据**  
   可选地加入现有腾讯 200d 向量的余弦相似度，但不训练、不更新、不注入任何新向量。

7. **冻结后盲评**  
   权重和规则必须在查看新测试集结果前冻结，同时报告准确率、宏平均、覆盖率、MFS 基线和置信区间。

### 预期与统计门槛

- 当前不一致金标上的保守估计：23-27/38（61%-71%）。
- 修正为真正 HowNet 义项后的工程估计：26-30/38（68%-79%）。
- 以上只是顾问预测，不是实验结果。
- 38 句中至少达到 **26/38 = 68.4%**，其 95% Wilson 下界才超过 50%；25/38 的下界约为 49.9%。

### 不推荐在当前阶段引入

- CRF：没有序列标注数据可训练。
- 依存句法：可留到第二阶段，当前短句中词性和固定搭配更划算。
- GNN：尚无可靠图边、训练目标或足够数据，成本高且无法定位收益来源。

## 2026-07-20 / 阶段 6：与 Semantic Graph 方向的关系

### 相符的部分

该方案与“使用 Semantic Graph 表示并推理语义”相符。推荐图结构为：

```text
目标字符跨度
  -> 复合词/上下文词节点
  -> HowNet 候选义项节点
  -> 义原与关系节点
  -> 激活竞争
  -> 选择义项
```

可使用的边包括：

- `covers`：复合词覆盖目标字符。
- `has_sense`：词项连接候选义项。
- `has_sememe`：义项连接 HowNet 义原。
- `left_of` / `right_of`：记录局部顺序。
- `has_pos`：记录词性或句法角色。
- HowNet 内部定义的语义关系。

这比把语义压成“科技/生活”或四轴更接近真正的 Semantic Graph。

### 没有重新制造 embedding

推荐方案**不训练新的 embedding，不建立新的稠密向量空间，也不恢复 Haibo 1.0 的 embedding 注入**。

- 第一版可以完全不用腾讯向量，只使用目标跨度、复合词、词性和 HowNet 图。
- 第二版可将腾讯余弦相似度作为一条弱边加入。
- 即使对现有腾讯向量做平均，也只是临时派生原型，不是训练新的 embedding；为避免概念混淆，建议第一版不物化这种原型，而是按需计算相似度。

## 2026-07-20 / 阶段 7：Semantic Emergence 的理论边界

需要区分两个不同命题：

### 命题 A：Semantic Graph 能否完成消歧？

HowNet 义项/义原图可以用于验证这个命题。若目标锚定的知识图在盲测上超过平面规则和 MFS，可说明结构化语义关系具有工程价值。

### 命题 B：语义能否从 Token 关系中自然涌现？

HowNet 方案不能单独验证这个命题，因为 HowNet 已经注入人类整理的语义知识，腾讯词向量也已经从大规模语料中预训练。

因此建议建立三层对照：

1. **符号语义图基线**：HowNet + 目标跨度 + 复合词，不用腾讯向量。
2. **固定 embedding 增量**：加入腾讯余弦边，测量相对提升。
3. **Token 底座实验**：优先复用 BriLLM 官方模型/代码或等价的最小 Token 层，移除 HowNet 义项标签，检验上下文活动能否形成语义簇。若必须自建最小 Token Graph，它只能作为实验夹具，不能作为 Haibo 的创新贡献。

只有第三层能够直接支持“Semantic Emergence”主张；第一、二层的职责是建立可解释基线和分离变量。

## 2026-07-21 / 阶段 8：BriLLM v8 正文复核

### 论文信息

- 标题：*BriLLM: Brain-inspired Large Language Model*
- 作者：Hai Zhao、Hongqiu Wu、Dongjie Yang、Anni Zou、Jiale Hong
- 机构：上海交通大学
- 版本：arXiv v8，2025-09-08
- 正文：[arXiv:2503.11299](https://arxiv.org/abs/2503.11299)
- 公开资源：论文列出了 BriLLM 0.5 的 GitHub 代码和 Hugging Face 模型。

### BriLLM 已经实现的部分

BriLLM 将词表中的每个 Token 固定映射到一个专属节点。节点间使用可学习的有向边传播信号，最后以候选节点的信号能量选择下一个 Token。它因此已经覆盖：

1. Token 节点化；
2. Token 节点间动态信号传播；
3. 基于信号能量的 next-token prediction；
4. 使用 Token 共现频率进行稀疏训练；
5. 节点级追踪和组件化编辑的初步框架。

因此，Haibo 不应再把“构建 Token Graph”或“在 Token 节点间传播信号”作为自身创新目标。BriLLM 应被视为相关先行工作、实验底座或必须比较的基线。

### BriLLM 没有实现的部分

论文第 4 页明确规定：每个 vocabulary token 对应唯一节点，节点语义保持固定。以“苹果”为例，无论表示公司还是水果，都只能进入同一个 Token 节点。上下文可以改变经过该节点的信号，但 BriLLM 没有形成：

```text
苹果 Token
  -> Apple Inc. Semantic Node
  -> 水果 Semantic Node
```

论文也没有实现或验证：

- 一词多义的动态拆分；
- 同义表达向同一概念节点合并；
- 无监督 Semantic Node 形成；
- Semantic Relation 归纳；
- 跨句、跨轮的持久语义状态；
- 目标、约束、意图和结构规划；
- Semantic Workspace 的输出反馈更新。

因此，BriLLM 的 Static Semantic Mapping 在当前实现中更准确地说是 **Token ID 到专属节点的静态映射**，而不是上下文相关的词义或概念映射。

### 对“非表示学习”的技术判断

论文将 BriLLM 定位为 non-representation learning，但实现仍包含：

- 32 维节点信号和节点偏置；
- 每条边的 `32 x 32` 权重矩阵；
- GeLU 和正弦/余弦位置编码；
- 对历史节点的 attention 权重；
- cross-entropy、AdamW 和反向传播。

所以它确实取消了传统共享 Token embedding lookup 的中心地位，但并没有取消高维向量状态和矩阵学习。“完全可解释”和“彻底非表示学习”应视为论文主张，而不是已经充分实验证实的事实。

### 实验证据强度

论文实验使用中英文 Wikipedia 各超过 1 亿 Token、4,000 Token 词表、长度 32 的训练序列、8 张 A800 和约 1,500 个训练 step。稀疏后中文模型约 2.19B 参数，英文模型约 0.96B 参数。

目前证据主要支持：BriLLM 可以稳定降低训练 PPL，并产生有限的序列续写。论文没有提供与 GPT-1/Transformer 的公平基准、验证集 PPL、长上下文实验、多模态实验、语义消歧实验或语义涌现实验；展示的测试集续写多数不连贯。因此内部文档中的“BriLLM 已证明该方向”应收紧为：

> BriLLM 提供了 Token 节点信号传播可以通过 next-token 目标训练的初步可行性证据。

它没有证明 Token 活动会自动形成 Semantic Graph，也没有证明后续 Semantic Workspace 有效。

### 对 Haibo 研究边界的修正

Haibo 的起点应从 BriLLM 已覆盖的 Token 层之后开始：

```text
BriLLM 或等价 Token 底座
固定 Token 节点 + 上下文相关信号传播
        ↓
Haibo Semantic Emergence
动态语义绑定与义项拆分
        ↓
Semantic Node 形成和关系固化
        ↓
Persistent Semantic Graph / Workspace
        ↓
Context、Intent、Constraint、Planning
```

新的核心科学问题是：

> 在 BriLLM 一类固定 Token 节点模型之上，能否从上下文相关的活动路径中，无监督形成稳定、可复用、持久的 Semantic Node 和 Semantic Relation？

### 建议替换的核心假设链

1. **H-SG-1：语义分区**  
   不同语义上下文的 Token 活动模式可以无监督形成稳定分区。
2. **H-SG-2：节点固化**  
   稳定分区可以固化为可复用的 Semantic Node，而不是一次性聚类标签。
3. **H-SG-3：关系形成**  
   Semantic Node 之间可以从共同激活、事件结构和时序中形成可解释关系。
4. **H-SG-4：持久状态**  
   节点和关系可以跨句、跨轮更新，组成 Persistent Semantic Graph。
5. **H-SG-5：下游价值**  
   该图能够改善上下文一致性、目标遵循、结构规划或语言生成。

### 与传统 WSD 的边界

上下文消歧本身已有长期研究，不能单独构成 Haibo 的创新。Haibo 的潜在贡献必须超越“判断苹果是公司还是水果”，落在：

> 将无监督形成的上下文语义分区固化为持久、可演化、可建立关系并能参与规划的 Semantic Graph。

## 最终建议摘要

1. 当前 50% 不是可信的语义天花板，且尚未超过 52.6% 的逐词多数基线。
2. 当前最大风险不是缺少新理论，而是任务定义和评估协议不足以区分真实提升与测试集适配。
3. 立即进入 P0-R，先修义项、金标、目标跨度、基线和盲测。
4. 最小实现采用目标锚定的字词 lattice 与 HowNet 义项图，不需要新 embedding。
5. 该实现符合 Semantic Graph 工程方向，但不能被直接解释为语义自然涌现。
6. BriLLM 已覆盖 Token 节点化和信号传播；Haibo 不应重复构建 Token Graph，而应研究 Token 活动到 Semantic Node 的跃迁。
7. 后续必须用分层对照分别测量 HowNet 知识、固定腾讯向量、BriLLM/Token 底座和 Haibo Semantic Emergence 层的贡献。
8. “BriLLM 已证明方向”应改为“BriLLM 提供了 Token 节点传播可训练的初步可行性证据”。

5. **命令行入口没有执行 B3 协议**
   - 入口未核对 manifest。
   - 未调用输入验证器。
   - 未调用输出验证器。
   - 未生成预测文件 SHA-256。

## 2026-07-22 / 阶段 11：P0-R5 冻结包独立验收

### 验收结论

本版的 manifest 中 10 个条目全部存在且 SHA-256 匹配；20 个原型均为 200 维；scorer 已加入三方 ID 唯一性检查；输入验证器也加入了目标词数量约束。这些改进有效，但构建数据、旧句隔离、入口完整性和测试证据仍有阻断问题。

### 阻断问题

1. **旧 60 句分支存在缩进错误，开发集只剩 41 条**
   - 9 个目标在旧 38 句中共有 32 条，在旧 60 句中共有 26 条，应合计 58 条。
   - `p0_r5_build.py` 的旧 60 句分支把 span 检查、append 和 `old_norm.add()` 放在 `for e in entries` 循环之外。
   - 因此每个目标只保留最后一条旧 60 数据：26 条只进入 9 条，最终得到 `32 + 9 = 41`。
   - 冻结配置中的 MFS、阈值和开发报告均基于错误的 41 条数据，必须作废。

2. **旧句去重产物不完整且运行时未使用**
   - 两批开发材料实际有 58 条规范化唯一句，`p0_r5_old_sentences.json` 只有 41 条。
   - `p0_r5_predict.py` 调用 `vi.validate(data)`，没有加载或传入冻结的旧句集合。
   - 输入验证器的默认参数是空集合，因此即使去重文件完整，B3 入口仍不会执行去重。
   - 独立 120 条合法分布反例中加入一条旧句，验证仍通过。

3. **输入验证器会放过 `sense_name` 泄漏**
   - 禁止键只搜索 `label`、`gold` 和 `intended`，遗漏协议明确禁止的 `sense_name`。
   - 独立反例同时包含旧句和 `sense_name` 字段，仍返回 `True`。

4. **字符跨度游标在 OOV token 后停止前进**
   - 构建和预测的 `extract_ctx()` 都只在 `w in kv` 时执行 `cp = we`。
   - 普通 OOV token 既不加入向量，也不更新字符游标，后续所有 token 的跨度都会向前错位。
   - 这会错误判断目标重叠、污染上下文 token，并直接干扰本实验要诊断的词表覆盖问题。

5. **单命令入口仍不校验 manifest**
   - 入口完成了输入验证、预测、输出验证和预测 SHA-256，这是有效改进。
   - 但源码没有读取或核对 `P0-R5_frozen_manifest.sha256`；运行前无法证明配置、原型、义原映射和验证器仍是冻结版本。
   - 外部腾讯词向量也没有在运行时核对记录哈希。

6. **输出一致性仍未真正验证**
   - 验证器只要求 `resolved_by` 属于四个层名，没有验证该层确实产生了 `cascade_B`。
   - 不要求 `target_span_valid` 为 `true`。
   - 不重算或核对 `L5_best_margin`，也不要求 L5 score keys 与候选集完全相等。
   - 独立反例中的 `target_span_valid=false`、伪造 margin 和与 independent 层不一致的 `resolved_by=L3` 仍通过。

7. **冻结包没有测试及测试日志**
   - manifest 不包含 `p0_r5_tests.py`、`test_log.txt`、冻结脚本或独立 manifest verifier。
   - `p0_r5_freeze.py` 只执行一轮合成 dry-run，没有运行输入负例、输出一致性、scorer 重复 ID、L3 正例/弃权例等测试。
   - 因此“测试通过”没有可审计证据。

8. **dry-run 覆盖不足**
   - 合成句只有“测试 + 目标词 + 句子编号”，主要覆盖无复合词的普通路径。
   - 未覆盖 L3 命中、HowNet 查询失败、L4 命中、L5 无上下文、MFS 回退、旧句拒绝、非法输出和 manifest 篡改。

9. **开发报告不满足诊断门槛**

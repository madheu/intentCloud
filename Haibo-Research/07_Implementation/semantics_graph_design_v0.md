# Semantics Graph v0 — 围合消歧设计

## 2026-07-19 | 从 Token Graph 错误修正

---

## 一、之前错在哪

**Token Graph（之前的错误设计）：**

```
节点 = 词（苹果, 手机, 甜, 树）
边 = 词共现频率
问题： "比"、"这款"在科技类和水果类句子中都出现
       → 污染信号 → 所有 11 句判为"不确定"
```

**Semantics Graph（正确设计）：**

```
节点 = 语义概念（科技类, 水果类, ...）
边 = 概念关系强度
word→concept = 归属关系（一个词可属多个概念）
"比" 不属任何概念 → 不贡献信号
```

---

## 二、核心架构

```
输入词序列
    ↓
[word→concept 映射表]
    ↓
概念激活向量（每个概念 = 被多少输入词激活）
    ↓
[如果歧义词——比较关联概念的激活强度]
    ↓
输出：歧义方向 / 不确定
```

### 2.1 概念节点

每个语义区域抽象为一个概念节点。节点本身没有"向量"——它只是一个激活计数器。

```
概念节点: 科技类
  归属词: 手机, 芯片, 系统, 屏幕, 应用, 发布, 商店, 生态, 软件, 硬件,
          服务, 隐私, 设计, 零售, 供应链, 开发者, 营收, 价格, 产品, 品牌

概念节点: 水果类
  归属词: 树, 甜, 采摘, 种植, 营养, 果汁, 果农, 丰收, 品种, 冷藏,
          成熟, 开花, 修剪, 含糖量, 有机, 果皮, 口感, 色泽, 保鲜

概念节点: 公司类
  归属词: 员工, 上市, 财报, 总部, 收购, 部门, 市值, CEO, 工厂

概念节点: 颜色类
  归属词: 红, 绿, 黄, 颜色, 光泽, 表皮

概念节点: 动物类
  归属词: 吃, 营养, 维生素, 健康, 生长  (共享于水果和动物)
```

### 2.2 歧义词→多概念映射

关键的改进：歧义词本身**不决定激活方向**——它只把激活强度"路由"到多个概念节点。真正决定方向的是**其他非歧义词**。

```
"苹果":
  → 科技类（权重 1.0）：作为公司名时
  → 水果类（权重 1.0）：作为水果时
  → 公司类（权重 0.8）：作为商业实体时
  → 颜色类（权重 0.3）：苹果的红色/绿色属性

"比":
  → （不属任何概念）中性词，不激活任何概念

"这款":
  → （不属任何概念）中性词，不激活任何概念
```

### 2.3 激活规则

```
输入: "这个苹果比上一代便宜了五百块"
词集: {苹果, 比, 上一代, 便宜, 五百, 块}

Step 1: 每个词查找其归属的概念
  "苹果"   → 科技类, 水果类, 公司类
  "上一代" → 科技类（产品代际概念）
  "便宜"   → 科技类（价格概念）
  "五百"   → 科技类（价格数字）
  "比"     → 无
  "块"     → 无

Step 2: 概念激活计数
  科技类: 被 {苹果, 上一代, 便宜, 五百} 激活 → 4
  水果类: 被 {苹果} 激活 → 1
  公司类: 被 {苹果} 激活 → 1

Step 3: 歧义判断
  歧义词"苹果"的候选概念: 科技(4), 水果(1), 公司(1)
  排名: 科技(4) > 水果(1) × 1.5 → 科技
  → 输出: "科技"
```

### 2.4 边界处理

```
输入: "这个苹果很好吃，而且设计也很漂亮"
词集: {苹果, 好吃, 设计, 漂亮}

  "苹果"   → 科技类, 水果类, 公司类
  "好吃"   → 水果类（味觉概念）
  "设计"   → 科技类（工业设计概念）
  "漂亮"   → 通用形容词（中性或概念归属弱）

  科技类: 被 {苹果, 设计} → 2
  水果类: 被 {苹果, 好吃} → 2
  比率: 2/2 = 1.0 < 1.5 → "不确定"
```

## 三、和 Token Graph 的关键区别

| 维度 | Token Graph（错的） | Semantics Graph（对的） |
|------|:------------------:|:----------------------:|
| 节点 | 词 | 概念 |
| 边 | 词共现频率 | 概念关系 |
| "比"的处理 | 污染信号 | 不产生激活 |
| 扩散 | 词→词传播噪声 | 词→概念计数 |
| 输出 | 比较两侧邻居权重和 | 比较概念激活计数 |
| 需要的计算 | 共现统计 + 边归一化 | 一个 lookup 表 |

**Token Graph 的"全部不确定"问题在 Semantics Graph 中自然消失**——因为"比"和"这款"不属于任何概念区，它们不产生激活，也就不会污染信号。

## 四、验证方案

### 4.1 测试用例（和 P_Resolve-08 相同）

| 输入 | 预期 | 说明 |
|------|:----:|------|
| "这个苹果比上一代便宜了五百块" | 科技 | 核心科技句 |
| "苹果发布了新款手机" | 科技 | 动词+产品 |
| "今年苹果的芯片性能提升很大" | 科技 | 技术名词 |
| "苹果的屏幕显示效果很好" | 科技 | 硬件名词 |
| "苹果应用商店的规则更新了" | 科技 | 服务名词 |
| "这个苹果比上一代更甜" | 水果 | 核心水果句 |
| "苹果的采摘季节到了" | 水果 | 农业名词 |
| "今年的苹果果肉很甜" | 水果 | 味觉+果肉 |
| "苹果正在开花" | 水果 | 植物生长 |
| "苹果的含糖量很高" | 水果 | 营养指标 |
| "这个苹果很好吃，而且设计也很漂亮" | 不确定 | 混合语境 |

### 4.2 成功标准

- 10/11 不判"不确定"（混合句允许不确定）
- 正确率 ≥ 80%
- 如果全部"不确定" → 概念分组错了（词表覆盖问题）

## 五、实现路径

### Phase 1（当前）— 手写 Semantics Graph
- 30-50 个概念节点
- word→concept 归属表（手写）
- 推理：查表 → 计数 → 比较
- 不做的：自动建图、学习归属权重

### Phase 2 — 扩展
- 从维基百科自动构建 word→concept 归属（一个句子出现的概念词集合 → 句子的概念标签）
- 增加概念节点到 100+
- 增加概念间边权重（概念共现关系）

### Phase 3 — 集成
- 输出歧义标签 → 修改 LLM prompt
- 保留跨轮次的激活状态（复用 H16 的会话管理）

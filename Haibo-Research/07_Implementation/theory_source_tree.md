## 一、认知语言学（Cognitive Linguistics）

### Frame Semantics（框架语义学）

- **来源**：Charles Fillmore, 1970s-80s
- **核心主张**：一个词激活一个完整的语义框架，框架由一组语义槽（slot）和默认填充词（default filler）组成
- **在海波中的用法**：
  - 概念节点 → 框架
  - 词→概念归属 → 槽填充
  - 围合消歧 → 框架竞争（哪个框架在句子中被激活得最多）
- **参照资源**：FrameNet（伯克利）

### Prototype Theory（原型理论）

- **来源**：Eleanor Rosch, 1970s
- **核心主张**：类别没有严格边界，有中心成员和边缘成员。"椅子"的中心成员是四腿靠背椅，"豆袋椅"是边缘成员
- **在海波中的用法**：
  - 框架内的填充词不需要"全部命中"——命中中心词得高分，命中边缘词得低分
  - 图扩散的激活分布天然符合原型理论：中心词附近扩散强，边缘弱
- **与现有实验的关系**：P0.10 的阈值 1.5 就是在说"中心成员得分需要比边缘成员高 50% 才能确认"

### Conceptual Metaphor（概念隐喻）

- **来源**：Lakoff & Johnson, 1980
- **核心主张**：抽象概念通过具体经验来理解。"时间就是金钱"——用金钱的框架来理解时间
- **在海波中的用法**：（预留，尚未使用）
  - 跨框架映射：一个句子可以同时激活多个框架，框架之间的映射关系解释隐喻
  - 例如"花钱如流水" → 消费框架 + 水的框架同时激活

## 二、NLP 语义理论

### Semantic Role（语义角色）

- **来源**：PropBank, FrameNet, VerbNet
- **核心主张**：谓词（动词/名词）的论元承担特定的语义角色：Agent、Patient、Instrument、Location、Time、Cause、Purpose、Manner
- **在海波中的用法**：
  - 图的边类型可以直接使用语义角色
  - "苹果公司发布了新手机" → 发布(Agent=苹果公司, Patient=新手机)
  - 不需要重新设计边类型
- **与现有实验的关系**：布尔 4 轴中没有语义角色维度——这是一个缺失

### Event Semantics（事件语义学）

- **来源**：Davidson, 1967; Parsons, 1990
- **核心主张**：事件是语义的基本单位。一个句子描述一个事件，事件有参与者、时间、地点
- **在海波中的用法**：
  - 将"事件"作为框架的重要类别——事件框架不同于实体框架
  - 区分"苹果公司"（实体框架）和"发布了新手机"（事件框架）

### Parsing（句法分析）

- **来源**：依存语法、短语结构语法
- **核心主张**：词与词之间有句法关系（主谓、动宾、定中）
- **在海波中的用法**：（预留）
  - 句法关系可以作为图的边的另一种类型（当前未使用，因为 P0 系列聚焦于词汇级消歧）
  - 如果需要处理长距离依赖（从句、嵌套），句法分析可能是必需的

## 三、知识表示

### Ontology（本体论）

- **来源**：哲学 → 人工智能（Gruber, 1993）
- **核心主张**：知识可以被形式化为概念和概念之间的关系。上层本体提供最基础的类别划分
- **在海波中的用法**：
  - 布尔 4 轴（物/事/质/序）直接来源于上层本体：Entity/Event/Property/Relation
  - 如果 4 轴不够扩展，方向不是自己发明新轴——而是从已有本体中取出更多类别
- **参考本体**：SUMO, DOLCE, WordNet

### Knowledge Graph（知识图谱）

- **来源**：Google, 2012; 语义网
- **核心主张**：实体-关系-实体的三元组（subject-predicate-object）
- **在海波中的用法**：
  - 图的基本数据结构天然是三元组：`(apple, is_a, fruit)` 或 `(apple, produces, phone)`
  - 当前实验直接用了这个结构（词→概念 即 subject→is_a→concept）
- **与现有实验的关系**：P0.10 的分层结构（词→子概念→大类）就是知识图谱的层次分类

### Description Logic（描述逻辑）

- **来源**：OWL, RDFS
- **核心主张**：用逻辑公理描述概念之间的关系（子类、等价、互斥、约束）
- **在海波中的用法**：（预留）
  - 当需要确保图的一致性时（如"一个实体不能同时是两个互斥类的成员"），描述逻辑提供了形式化工具
  - 当前未使用，因为图规模还小

## 五、使用方式

当需要决定"海波的 X 功能应该怎么设计"时：

1. 查这棵树——有没有已有的理论覆盖了这个功能？
2. 如果有 → 直接用那个理论的框架，不要自己发明
3. 如果没有 → 确认这个功能是否真的需要，还是可以砍掉
4. 如果确实需要且没有理论覆盖 → 这才是海波创新的地方

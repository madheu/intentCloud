# Token Graph 围合设计（第一版草图）

## 2026-07-18 | 从 P0 终点出发

---

## 一、问题

P0 证伪了"词向量能区分语义歧义"。  
但 P0 没有证伪"词序列中的关系结构能区分语义歧义"——实际上 P0.4 间接证实了这个方向：鲸鱼和汽车的句子比苹果歧义词分开得更好，说明**序列中的多词联合约束力远大于单词。**

## 二、围合的直觉

一个词的语义不是由这个词自身携带的，是由同时出现的其他词"围合"出来的。

```
"这个苹果比上一代便宜了五百块"

围合词集: {苹果, 比, 上一代, 便宜, 五百, 块}
邻居词域: {手机, 价格, 发布, 芯片, 系统...}  →  苹果=科技

"这个苹果比上一代更甜"

围合词集: {苹果, 比, 上一代, 更, 甜}
邻居词域: {树, 采摘, 种植, 营养, 果汁...}  →  苹果=水果
```

围合的两个条件：
1. **内聚**：围合词集内部的词互相有强边
2. **分歧**：两个围合区域的邻居不重叠（或重叠很小）

## 三、图结构

### 节点

最小规模：P0 用的 4 个歧义词 → 每个歧义词 + 各自围合词集，约 25-30 个节点。

```
苹果节点 + 科技围合词: 手机, 发布, 芯片, 系统, 屏幕, 应用, 便宜, 上一代, 五百, 价格
苹果节点 + 水果围合词: 甜, 树, 采摘, 种植, 营养, 果汁, 更, 口感
```

### 边

边权重 = 词对的共现频率（从 P0.3 的维基百科语料统计）

```
例子：
苹果 ─ 手机: 共现在科技类句子中出现的次数
苹果 ─ 甜: 共现在水果类句子中出现的次数
手机 ─ 价格: 共现在同句中的次数
```

边权重在 0-1 之间归一化（每对词一次共现 + 1/词汇表大小）。

### 围合检测逻辑（核心）

给定输入句子 S = {w1, w2, ..., wk}：

1. **激活**：S 中每个词激活对应节点，初始激活值 = TF-IDF（防止"的、了、是"主导）
2. **扩散**：激活值沿边传播 1-2 步（不迭代到收敛，防止淹没问题）
3. **语境定位**：比较歧义词的扩散激活分布——
   - 如果 "苹果" 的 2 步邻居中 "手机" 群的激活和 > "水果" 群的激活和 → 科技歧义
   - 反之 → 水果歧义
   - 如果两者相近 → 无法判断（这是允许的结果）

### 关键参数

| 参数 | 初始值 | 作用 |
|:----|:-----:|------|
| 扩散步数 | 2 | 太大淹没问题（P0.5 教训），太小捉不到围合 |
| 初始激活 | TF-IDF | 过滤高频停用词 |
| 歧义判断阈值 | 1.5 倍 | 两类激活和超过 1.5 倍才做判断，否则"不确定" |

## 四、这张图能验证什么

```
输入："这个苹果比上一代便宜了五百块"  →  图输出: 科技 ✅
输入："这个苹果比上一代更甜"          →  图输出: 水果 ✅
输入："苹果是一种水果"                →  图输出: 水果 ✅
输入："苹果发布了新手机"              →  图输出: 科技 ✅

指标：4 句正确率 ≥ 75% → 围合概念可行
      4 句正确率 < 50% → 围合在现有设计下不可行
```

## 五、半小时能做什么

1. 确认数据结构：节点 + 边权重（dict + dict，约 30 行）
2. 写围合检测逻辑：激活 → 扩散 1 步 → 对比邻居域（约 20 行）
3. 手写 5 句测试用例，人工标答案
4. 跑 → 看正确率

不做的：自动建图、大规模语料训练、复杂扩散算法。只用 P0 已有的手写数据。

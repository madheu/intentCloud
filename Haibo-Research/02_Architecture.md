# 架构文档（Haibo 2.0 概念草案）

> 更新：2026-07-18 | Haibo 1.0 架构（BilingualInjector）已废弃。
> 以下为 2.0 方向的概念架构。尚未有代码实现。

---

## Haibo 1.0 架构（已废弃）

```
Input → TOPIC_MAP → acts → diffusion → a* → injection → LLM → output
                                              ↓ 注入层是瓶颈
                                          I(a*; y)≈0
```

**注入层已废弃。** 图→LLM 的直接控制通道被实验证伪。所有依赖它的链路（chat_with_haibo.py 旧版）不再使用。

---

## Haibo 2.0 概念架构

```
Input Text
    │
    ▼
┌──────────────────────┐
│ Token Layer          │  ❓ 未实现

│ 节点 = 词语          │
│ 边 = 共现频率/PMI    │
│ 输入 = 句子中 token  │
│        的初始激活     │
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ Semantic Layer       │  ❓ 未实现（核心开放问题）
│ Semantic Emergence   │
│                      │
│ 从 Token 关系中的    │

└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ Context Layer        │  ❓ 未实现

│ 稳定状态             │
│ 苹果+{手机,发布会}   │

           ▼

           ▼

```

## 当前可复用组件（来自 Haibo 1.0）

| 组件 | 能否用于 2.0 | 原因 |
|------|:-----------:|------|
| 扩散引擎（diffuse_activation） | ⚠️ 可能需要改造 | Token Graph 的扩散算法可能不同 |
| GraphInterpreter → Decision | ❌ 依赖语义节点 | 2.0 无手编节点 |
| PromptBuilder | ⚠️ 方向正确但需重写 | 语境→prompt 的翻译逻辑会完全不同 |
| StrengthRegulator | ❌ 依赖弹性地图 | 2.0 无手编路径 |
| H17 语义理解层（5 模块） | ⚠️ 可复用但优先级低 | 有独立于注入的价值 |
| Haibo Memory MCP Server | ✅ 独立可用 | 不依赖图结构 |
| common_sense.json（36 节点） | ❌ 手编 | 2.0 语义要从 Token 涌现，不是手编 |

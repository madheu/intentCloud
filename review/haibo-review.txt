海波项目审查起点文档
项目定位
海波是一个基于动态异构图的自适应语义网络，作为认知架构位于大语言模型的上游。核心理念：语言是思维在低维空间的投影，海波组织语义，LLM执行语言生成。海波不存储对话记录，不存储向量坐标，只存储节点之间的语义关系及其演化历史。

核心机制
双层时间尺度动力学：快系统激活扩散，慢系统权重更新

综合更新律：赫布学习 + 参考模型拉回 + 动量阻尼 + 死区 + 投影

锚点系统：概念锚点、拓扑锚点、结构锚点

双语者注入：节点embedding加权注入LLM输入层

视角转换器：恐惧链专属处理

多轮对话上下文管理：会话结束清空，内化需用户明确确认

已完成验证
H10-H19实验链路贯通，包括端到端链路、双海波拓扑演化、控制曲线校准、弹性地图、视角转换器、多轮对话管理、多维语义理解层（指代消解、纠正分析、矛盾处理、情绪球、结构化记忆）。160+单元测试通过。

核心未解决问题
交互式对话中海波无法稳定锚定自身身份，LLM预训练人格覆盖海波身份设定

扩散结果被下游模块正确接收后，仍无法转化为有效的生成控制信号

LLM接收海波引导信号后出现沉默、身份泄漏、预训练人格覆盖

输入层仅有关键词匹配，缺少语义泛化能力

缺少LLM输出到海波内部状态的反馈回路

当前工程目标
H20待完成：常识层扩展（元认知节点：如何提问、如何记忆、如何内化、如何认识自己/他人）、编译层实现（输入编码+输出解码）、节点生长机制（自动扩展匹配文本）。

当前理论缺口
海波认知状态空间的数学定义未完成——无法进行严格的稳定性分析

LLM作为反馈源的闭环控制系统尚未建模

系统从"外部控制器"到"自主认知系统"的演化路径未清晰定义

综合更新律的全局稳定性缺少严格证明

审查起点建议
审查应从以下核心问题开始：

海波当前是否构成了一个闭环认知动力系统？ 如果不是，缺什么？

海波的控制信号是否被LLM正确接收？ 什么证据支持或反驳这一点？

H20的设计是否解决了当前核心问题，还是只是增加了更多模块？

海波的核心贡献应该被定义为什么？ 什么是可验证的"最小可行理论"？

【1/5】核心判断：海波不是一个闭环认知动力系统。

当前系统拓扑：

    user_input → diffuse_activation (fix W) → converged a* → update_weights (fix a*) → a* → BilingualInjector → LLM

这是一个开环前馈链。LLM的下游输出从不回到海波的状态方程中。
从控制论角度，这等价于一个基于事件的静态映射：

    a* = f(u, W)          [扩散稳态]
    W^+ = g(W, a*)        [权重更新一次]
    y = h(a*) → LLM        [输出到LLM，无返回]

没有反馈 → 没有闭环 → 没有闭环稳定性可言。这个系统的行为完全由初始条件（锚点）和每次的输入信号驱动，不存在自主动力学。

缺失项（重要性排序）：
    (a) 状态方程：没有在"交互时间尺度"上定义的状态演化。process_interaction 的调用是离散事件，由外部用户输入触发，不由系统自身的动力学决定。
    (b) 反馈回路：LLM输出 → 下一轮 input_signals 的映射不存在于代码中。
    (c) 控制律：没有定义"输入信号 u 如何根据内部状态生成"。

【2/5】反直觉的数学事实：已有模块的稳定性结论比想象中弱。

综合更新律"η + γ + K_d + Proj"的分析结论：

(a) 权重有界性由硬裁剪保证，不是由动力学保证。
    Proj[·, 0, 1] 防止 w 超出 [0,1]，但这等价于"用限幅器掩盖了不稳定的动态"。如果 γ = K_d = 0（学习模式），赫布项 η·a_i·a_j > 0 会使权重恒向 1 单调增长。裁剪后 w = 1 是一个饱和平衡点——系统卡在边界上，丧失了敏感性。

(b) 参考拉回 + 动量阻尼的参数比 η/γ = 10 意味着参考拉回是弱约束。
    稳态偏移量 Δw = (η/γ)·a_i·a_j（忽略死区和阻尼时）。在 η/γ = 10 下，a_i = a_j = 0.3 就能产生 Δw = 0.9，达到饱和边界。所以"始终锚定到参考值"的直觉是错误的——大多数情况下系统工作在饱和边界附近。

(c) 权重更新的二阶特征根 λ₁ ≈ 0.99。
    当 a_i·a_j 变化时，权重收敛到新稳态的时间常数 ~ 100 轮交互。系统对输入变化的响应是慢速衰减的振荡。

(d) 扩散迭代的收敛性取决于 W^T 的谱半径。
    当前代码中入度权重列和没有归一化约束。如果某节点积累了大量入边（权重趋近 1），列和 > 10，在 α = 0.1 下扩散会发散——饱和非线性会救场，但系统退化为"全节点激活 = a_max"的平凡解。

关键结论：这些不是参数可以调优的问题，是结构问题。任何一组参数都无法同时保证"赫布学习有效"和"扩散无条件收敛"——因为赫布学习会单调增长权重，而权重增长会破坏扩散的收敛性。

【3/5】LLM 在本架构中的可归属角色：既不是控制输入，也不是扰动。

控制输入 → 需要可建模、可预测的影响。LLM 的输出稳定性、延迟、上下文窗口长度都是不保证的。不能把 LLM 当作控制信号发生器。

扰动 → 需要有界且有统计规律。LLM 的"预训练人格覆盖"不是有界扰动，是结构性的模式切换——系统突然进入 LLM 的预训练分布，与海波的状态无关。

当前最准确的物理类比：LLM 是一个独立的动力系统（巨大的预训练状态空间），海波在它的输入边界上施加了一个微弱的偏置。这属于 boundary control 问题，海波的注入信号强度（std ≈ 0.49 vs input embedding std ≈ 0.015，差 33 倍）决定了它在强非线性（LLM 的内部动力学）面前的耦合强度。

换句话说，海波是通过一个弱耦合接口连接到了一个更强、更复杂的动力系统上。在这个设置下，海波输出的有界性无法保证 LLM 行为的有界性——LLM 可以自己"跳"到一个与海波状态无关的再生模式。

【4/5】H20 的评估：增加模块数量，不解决结构问题。

H20 的三个目标：
    - 常识层扩展（元认知节点）
    - 编译层（输入编码 + 输出解码）
    - 节点生长机制

这三个目标分别增加模块复杂度、增加接口、增加图规模。但没有一个目标：
    - 定义或测量 LLM 输出对海波状态的反馈路径
    - 建立扩散权重图谱半径的有界性保障
    - 验证 LLM 接口的耦合强度是否足够传递控制信号

H20 在解决"控制信号不被接收"的问题时，做法是"注入更多信号"（元认知节点 + 编译层）。但问题不是信号不够多，而是耦合强度不够以及 LLM 的内部动力学会覆盖外部输入。在没有解决耦合强度问题之前，增加输入信号的维数不会提升控制效果。

【5/5】如果要阻止这个项目失败，最低限度必须回答的问题。

问题 A（模型可识别性）：
    海波的状态空间是什么？维度是多少？什么是"一次交互"的数学定义？如何判断两次交互属于"同一状态"还是"不同状态"？

问题 B（输入-输出映射的可验证性）：
    给定固定输入 u_0，海波是否总是产生相同的输出 y_0？（确定性 / 随机性 / 路径依赖）如果输出不是唯一的，方差有多大？

问题 C（LLM 接口的校核）：
    海波的注入信号和 LLM 输出之间的互信息 I(a*; y_LLM) 是否显著大于零？如果互信息≈0，海波的控制信号不被接收，整个架构就是幻灭的。

问题 D（最小可行理论）：
    去掉 LLM，海波的扩散动力学本身是否是一个可独立验证的动力学系统？（即：能否在不需要 LLM 的情况下验证它的行为是有意义的？）如果不能，海波的理论依附于 LLM 的行为，而 LLM 行为无法提前预测——这是一个根本性的验证困境。

总结：项目当前处于"系统已经搭建，但系统行为仅由经验观察描述，没有数学保证"阶段。在回答上述四个问题之前，H20 及后续规划缺乏理论根基。继续增加模块而不建立形式化框架，将使项目陷入"模块越多，不可预测性越大"的正反馈陷阱。

【结论前置】海波当前处于"理论承诺超出工程交付"的状态。以下逐条给出风险评估，每条标注证据强度：Strong / Partial / Unknown。

【1/7】致命："闭环认知动力系统"的宣称是假的。  [Strong]

文档自己承认：缺少LLM输出到海波内部状态的反馈回路。当前系统拓扑：

    user_input → 提取 → 扩散 → 注入 → LLM 生成 → 结束

这不是闭环，是开环的前馈预处理器。ACT-R、SOAR、GWT 的核心都是闭环——行动改变环境，环境反馈修正认知模型。海波没有这个结构。

失败机制：即使 H10-H19 全部完美执行，只要输出不反馈回拓扑，系统就永远无法从经验中学习。用户对上一轮回答的满意度、纠正、否定——全部不影响图结构。对话结束一切归零（H16 by design）。这使得"演化"只发生在实验者的手动脚本里，不在运行时。

你必须回答：闭环缺失是设计决策还是待实现功能？如果是设计决策，请给出理论论证说明为什么闭环不必要。如果是待实现功能，它的优先级在哪里——H20 名单上没有它。

【2/7】致命：双语者注入作为控制信号不成立。  [Strong——H11-H19 实验数据自证]

项目自己的实验数据本身就证明了控制器失效：

    | 发现                                              | 含义                                              |
    |---------------------------------------------------|--------------------------------------------------|
    | MAX_INJECT=4（1.5B 上限）                         | 信号带宽极窄：4 个虚拟 token vs 500+ 真实 token       |
    | 扩散接上后 36 节点 → 截断到 4 个                   | 99% 的图信息被丢弃                                 |
    | 0.5B Instruct 60% seed 掉入预训练泄露              | 小模型无法承载注入信号                              |
    | 1.5B 3/3 通过但条件极端敏感                        | 成功依赖种子选择，非确定性控制                       |
    | logits cos 变化但不足以覆盖 RLHF 偏好              | 信号存在但力度不够                                  |
    | 恐惧方向稳定区间仅 [0.01, 0.05]                     | 可控区间极窄，超出即失控                             |

这是一个"控制器增益远小于 1"的放大-注入-衰减管道。你在用 1 瓦特控制 1000 瓦特。

失败机制：只要 LLM 参数量远大于注入信号维度，基座模型的预训练权重就永远是"赢了就继续"的强者。这是数量级差距，不是调参数能解决的。LoRA 微调可能是唯一路径——但那等于放弃"不修改 LLM 参数"的原则。

【3/7】致命："理解"模块不存在——输入层仅是关键词匹配。  [Strong]

文档自己承认输入层仅有关键词匹配，缺少语义泛化能力。这意味着海波目前不理解用户说什么——它以关键词为索引激活节点。用户说"那片深邃的蓝色"而不说"大海"，系统不会激活"大海"节点。

这是项目名本身（"语义组织"）与工程现状之间的根本矛盾。核心宣称是"海波组织语义"，但语义组织只发生在已有节点之间（激活扩散），从原始输入到节点的映射几乎不存在。

失败机制：在没有语义泛化能力的条件下，所有下游模块（扩散→解释→注入→生成）都建立在"用户必须说对关键词"的脆弱假设上。这不是认知架构，这是关键词匹配系统。

---

【4/7】严重：核心概念的形式化缺口未填补。  [Strong——文档自己列出]

文档列出三个理论缺口：状态空间未定义、闭环控制未建模、从外部控制器到自主认知系统的路径未定义。

关于 #3 的展开分析：当前海波是外部控制器——注入强度、激活阈值、视角转换参数全由配置/脚本设定。系统没有自主决策"多少注入才算够"的能力。StrengthRegulator 自动 clamp，但 clamp 到实验者预先扫描的弹性地图上——这仍是外部知识。

未知的未知：系统当前主循环速度（一次扩散约 0.01 秒）和 LLM 生成速度（约 20-30 秒/次）之间存在 2000-3000 倍差距。在人类认知中，这对应无意识处理和有意识处理的速度差。但海波没有利用这个差距——扩散只在调度时触发一次，然后 LLM 独占生成时间。在这 20-30 秒里，图是冻结的。

失败机制：如果不定义状态空间，就无法证明系统不会进入死循环或混沌。综合更新律的三项耦合可以很好地抑制短期振荡，但没有人证明它在上千次边更新后不会出现累积性漂移。锚点系统的拉回参数 γ 是手动设定的——γ 太小漂移累积，γ 太大等于禁止学习。

【5/7】中等：169 测试通过 ≠ 系统工作。  [Partial——需要看测试覆盖率和端到端验证设计]

单元测试证明的是每个函数在隔离条件下返回预期输出，不证明集成后的系统产生有意义的认知行为。从 H19 诊断记录看：
- A/B/C/D 四条件消融下全体退化——图控制层对 LLM 的影响仍然微乎其微

- 无法排除"prompt engineering + 随机采样"作为输出质量的解释

失败机制：如果成功标准停留在单元测试通过，而端到端验证仍然是人工扫读输出文本（"这句比那句好"），则永远不能排除安慰剂效应。

【6/7】中等：H20 像是功能堆积而非解决根本问题。  [Partial——需要看 H20 设计细节]

H20 的编译层输入编码实际上在解决"理解"缺失——这是应该做的。但元认知节点是单独的问题："如何提问、如何记忆、如何内化、如何认识自己/他人"——这些是最高层的认知功能，被放在和"大海""恐惧"同一个图里。

我不知道这个选择对不对——但我可以指出风险：如果元认知节点和内容节点共享同一套扩散机制和权重更新律，则元认知也会受赫布学习强化。使用越多权重越大——但元认知不应该因为频繁使用就变得更强大。激活扩散会在内容节点和元认知节点之间双向传递——一个关于大海的输入也可能激活"如何提问"节点，造成概念污染。

如果元认知需要独立结构（单独的子图/单独的动力学参数），现在就应该设计隔离机制，而不是放到 H20 再决定。

【7/7】低-中：哲学主张与工程实现的错位。  [Strong]

核心宣称"LLM只是嘴巴不是大脑"与工程现实存在系统性的错位：

1. LLM 承担了人格维持——"我是海波"在 system prompt 里，不在图结构里
2. LLM 承担了对话流畅性——图只输出 topic/tone/persona 三个字段
3. LLM 承担了"理解"——输入提取依赖关键词匹配，没有图结构理解
4. 没有 LLM，海波只是一组不说话的权重

这不是在批判哲学本身，而是指出哲学-工程差距是项目失败的潜在归因。当你对外宣称"LLM只是嘴巴"时，评审者期望看到 LLM 被严格限制在语言表达域。但实际上 LLM 承担了太多非语言功能。

失败机制：如果继续用"LLM只是嘴巴"对外宣传，遇到的第一轮同行评审就会用工程证据反驳这个宣称，导致项目信誉受损。这不是科学问题，是沟通策略问题——但在这个委员会里，我需要在早期指出来。

【对审查起点三个问题的直接回答】

Q1: 海波当前是否构成了一个闭环认知动力系统？
不是。缺少输出状态到输入状态的反馈回路（项目文档自己承认）。目前是开环前馈管道。仅当实验者手动修改配置/运行时，才形成"外部闭环"。

Q2: 海波的控制信号是否被LLM正确接收？
部分接收，但不足以覆盖基座模型先验。
- H11c/d：短词 embedding 在中间层 cos_sim=0.9998——信号不可区分。
- H13：恐惧方向 0.1 以上全部失控——信号有效窗口极窄。
- H19 四条件消融：全部条件含 prompt+injection 均不稳定——提示控制信号强度不足以独立工作。
"接收"是连续的（logits 有变化），但"正确接收"（注入信号主导生成方向）的证据不存在。

Q3: H20 的设计是否解决了当前核心问题？
编译层的输入编码（解决关键词依赖）是必要的。元认知节点和节点生长机制在当前阶段可能是范围蔓延——在没有证明基础控制链路可靠的前提下扩展模块数量，增加了调试复杂度但未增加可靠性。

【我应该被记住的一个判断】

【A1】"反馈"的三种不同含义——必须在同一个术语下区分

文献中"反馈"（feedback）至少指代三种不同的机制，认知科学界没有统一术语。以下是必须区分的三个层面：

──────────────────────────────────────────────
| 层级 | 名称              | 定义                              | 海波有吗？ |
|------|-------------------|-----------------------------------|-----------|
| L1   | 处理内反馈         | 同一处理单元内的迭代收敛            | ✅ 扩散循环 |
| L2   | 状态间反馈         | 上一轮输出影响本轮图状态            | ⚠️ 部分   |
| L3   | 学习反馈           | 输出效果修正系统参数                | ❌        |
──────────────────────────────────────────────

L1（处理内反馈）：激活扩散本身就是反馈循环——`a_{t+1} = a_t + α·(input + incoming - a_t)`。扩散在 10-50 次迭代内收敛到稳态。**在认知科学中，这对应"联结主义约束满足"（Rumelhart et al., 1986, PDP 框架），不是"反馈回路"意义上的反馈。**

我一开始犯了一个错误：用控制论的标准说"海波是开环的"，但**扩散这一层已经包含处理内反馈**。正确的表述应该是：海波在扩散层是闭环的，但在交互层是开环的。

L2（状态间反馈）：上一轮 LLM 的输出是否影响下一轮的图激活态？当前：H16 DialogContext 设计为会话结束后清空所有状态。所以**在 H16 设计下，L2 反馈只在单次会话内存在，会话间为零。**

L3（学习反馈）：输出效果修正系统参数（边权重）。当前：权重更新由 `process_interaction` 触发，但 update_weights_after_diffusion 只使用收敛后的激活值，不使用 LLM 输出。即使用户说"你回答错了"，这个信号也不会直接改变边权重。**L3 反馈完全缺失。**

---

【A2】无反馈认知系统的文献举证

严格来说，"无任何反馈的纯认知系统"在主流认知架构文献中**不存在**。但有几个接近的案例，它们的"无反馈"都有特定限定条件：

(1) **Fodor 的输入模块（Input Modules）**（Fodor, 1983, The Modularity of Mind）
    - 声称：感知模块（视觉、语言解析）是"信息封装的"——不接受来自高层认知的反馈。
    - 限定条件：Fodor 明确区分"输入模块"和"中央认知系统"。模块可以是前馈的，但完整的认知系统必须包含非模块化的中央系统，而中央系统就是靠反馈工作的。
    - 对海波的启示：如果你的目标是构建一个"语义组织模块"（而非完整认知系统），你可以用 Fodor 论证说"我只需要做 LLM 的输入模块"。但海波的文档定位是"认知架构"——那就超出了输入模块的范围。

(2) **早期 ACT-R —— 单一 production cycle 内的前馈**
    - 声明：ACT-R 的单个 production firing 是前馈的——匹配 → 选择 → 执行。没有反馈 per cycle。
    - 实际：ACT-R 从来不是"无反馈"的，因为 production 的执行修改了 goal buffer 和 declarative buffer 的内容，而这些改变直接影响下一个 production cycle 的匹配。**反馈在 cycle 之间，不在 cycle 之内。**
    - 对海波的启示：ACT-R 的"cycle 内无反馈"意味着你可以接受处理内无反馈，但状态间必须有反馈（L2）。

(3) **Collins & Loftus (1975) 激活扩散模型**
    - 声明：语义记忆中，激活从被激活的节点向外扩散，降低相关节点的检索阈值。
    - 实际：这只是一个检索机制，不是完整的认知系统。它没有目标管理、没有学习、没有输出选择。
    - 对海波的启示：海波的扩散层就是这个模型的直接等价物。但海波不满足于只做检索。

(4) **NARS（Non-Axiomatic Reasoning System, Wang, 2006）**
    - 声称：NARS 是基于经验的推理系统，经验修正真值。
    - 实际：NARS 的每个推理步骤都依赖于已积累的证据。信念的真值 = 频率 × 信度。每一个新的证据都更新信念——这本身就是反馈。NARS 不是无反馈系统。
    - 注意：Pei Wang 明确说过"NARS 的学习和推理是同一过程的不同方面"——这意味着没有学习反馈的 NARS 根本不存在。

(5) **Baars 的 Global Workspace Theory（无意识处理器的前馈性）**
    - Baars (1988/1997) 主张：无意识处理器是前馈的、高度专业化的、并行的。只有进入全局工作空间（conscious access）的内容才会被广播给所有处理器。
    - 关键点：这一轮广播的结果反馈给所有处理器，改变它们的内部状态。
    - 对海波的启示：GWT 同时包含前馈的无意识处理阶段和闭环的有意识广播阶段。两者缺一不可。

---

【A3】结论：必要反馈的最小定义

认知科学文献不支持"完全无反馈的认知系统"的存在——任何被称为"认知架构"的系统都至少需要 L2 状态间反馈。

**最小必要反馈 = 系统当前认知状态必须影响下一轮对输入的处理方式。**

这个最小定义的包含条件：

1. **状态持续性**：系统在下一次收到输入时，内部状态与上一次结束时不同
2. **状态相关性**：这个差异源自对上一次输出的处理
3. **状态作用**：这个差异以可测量的方式改变下一轮的处理结果

当前海波的状态间反馈（L2）是残缺的：DialogContext 在会话内维持状态，但 H16 明确设计为"会话结束后全部清空"。这意味着：

- 同一会话中的第 N+1 轮确实受第 N 轮影响 ✅
- 新会话的第一轮与上一会话的最后一轮没有状态关联 ❌

这是一个设计选择（安全理由），但它意味着海波的认知连续性**不会超过一次会话的长度**。

---

【B】H16 设计的冲突评估

H16 的"会话结束清空、内化需用户明确确认"设计与认知架构的最小反馈需求之间存在**结构性冲突**。

冲突矩阵：

────────────────────────────────────────────────────────────
| 认知需求                   | H16 设计            | 冲突等级 |
|---------------------------|---------------------|---------|
| L2 状态间反馈需要状态持续   | 会话结束后清空       | 🔴 高级  |
| L3 学习反馈需要自动权重更新 | 需用户明确确认        | 🟡 中级  |
| 内化需要从交互中自然积累    | 审核后才写入         | 🟡 中级  |
| 安全约束（不自动修改权重）  | 完全符合             | 无冲突   |
────────────────────────────────────────────────────────────

🔴 **高级冲突（L2）：状态持续性 vs 会话边界重置**

H16 在会话结束时重置所有话题、情绪、待处理纠正。这意味着：

- 海波每次会话都是"新生"的
- 不会因为上一轮会话中用户解释了某个概念，就在本轮自动理解它
- 用户必须在每轮会话中重新建立上下文

这是安全的（隐私、隔离），但与认知架构的核心主张（"演化学习"）直接矛盾。到目前为止，**海波所有的"学习"和"演化"都来自实验者手动运行的脚本，而不是来自真实交互。**

🟡 **中级冲突（L3）：内化门控 vs 非监督学习需求**

H16 要求用户明确说"记住这个"才触发内化。这在安全上是好的，但：

- 真实对话中用户很少说"记住这个"——大多数有用的学习发生在用户没有明确指令的情况下
- "用户的纠正"是隐形的学习信号。用户说"不是这样"——这就是反馈。但 H16 不把它当作学习信号，只把它排队等待用户确认再写入。
- H16 的设计本质上把内化的**所有责任推给了用户**：你必须明确告诉我该学什么。但在 ACT-R 中 base-level activation 的更新、在 SOAR 中 chunking 的产生——这些都是自动的，不需要用户"批准"。

解决方案空间（三个可选路径）：

────────────────────────────────────────────────────
| 路径  | 方案                 | 认知完整性 | 安全性 |
|-------|---------------------|-----------|--------|
| A     | 接受弱认知系统定位     | ❌         | ✅     |
| B     | 增加自动弱反馈机制     | ✅         | ⚠️     |
| C     | 分离状态反馈与学习反馈 | ✅         | ✅     |
────────────────────────────────────────────────────

**路径 A：接受"海波是弱认知系统"**

如果项目方愿意修改定位——海波不是一个完整的认知架构，而是一个"受控的语义组织器"——那么当前的 H16 设计是合理的。代价是放弃"自主认知系统"的宣称。

**路径 B：增加自动弱反馈（推荐但需谨慎实现）**

在 H16 中增加一条自动反馈管道：**LLM 的输出文本经过简单情感/相关性分析后，以低权重自动更新当前会话中的激活态（不是权重）。** 这样：
- L2 反馈在每个交互轮次内自动发生
- L3 学习反馈仍然由内化门控控制
- 权重变化速度从"0 或 1"变成"连续可调"

实现复杂度：低。只需要在 DialogContext 加一个方法：
```
context.auto_update_activation(llm_output, cloud, strength=0.1)
```

**路径 C：分离状态反馈与学习反馈（最推荐）**

这是从认知架构角度最干净的做法，也符合你的哲学框架。H16 的"会话结束清空"针对的是**学习反馈**（L3），但它错误地清空了**状态反馈**（L2）。修复方案：

1. L2 状态反馈：自动发生，不经过用户确认。H16 的 topic/emotion 继承可以保留会话间状态（用一个衰减后的摘要而非原始数据）
2. L3 学习反馈：仍然由内化门控控制，需要用户显式确认

实现方式：
```
# L2: 会话结束后，不丢弃，而是"衰减"状态到记忆
# 一小时后：保留 30% 的状态信息
# 一天后：保留 10%
# 一周后：完全消失

# L3: 仍然需要用户明确确认才修改边权重
```

这个方案既保留了 H16 的安全机制（没有自动 L3），又提供了认知架构需要的最小反馈（自动 L2）。

---

【最终判断】

**海波当前不能被称为一个完整的认知系统，不是因为缺少 LLM 输出到图状态的直接回路，而是因为 H16 的"会话结束清空"设计切断了认知系统需要的最小反馈——状态持续性。**

这不是一个不可修复的问题。路径 C（分离 L2 和 L3）可以在保留所有安全设计的前提下修复它。代价是增加 ~50 行代码实现一个衰减式的会话间状态记忆。

如果选择不接受这个方案（坚持完全清空），那么海波应该被重新定位为"每次会话独立的语义组织工具"而不是"认知架构"——这两个定位都是合法的，但项目文档需要统一到其中一个。

议题：赫布学习与扩散收敛是否数学兼容？

──────────────────────────────────────────────────────────────────────────
一、谱半径分析
──────────────────────────────────────────────────────────────────────────

扩散迭代（忽略 clip 非线性）：

    a^(k+1) = ((1-α)I + α·W̃)·a^(k) + α·u

其中 W̃_{i,j} = w_{j→i}。迭代矩阵 A = (1-α)I + α·W̃ 的特征值为：

    λ_i(A) = 1 − α + α·μ_i(W̃)

收敛条件 |λ_i(A)| < 1 给出（对实特征值）：

    ρ(W̃) < 1  即：扩散收敛的充要条件是 W̃ 的谱半径 < 1

Perron-Frobenius 给出充分条件：每节点入度列和 < 1。

这对海波的直接含义：赫布学习的本质是使 w_{i→j} 增长。
当权重增长 → 列和增长 → ρ(W̃) 增长 → 逼近并超过 1 → 扩散发散。

──────────────────────────────────────────────────────────────────────────
二、反例构造（已验证可复现）
──────────────────────────────────────────────────────────────────────────

图：k 个可演化节点，全连通双向边，初始 w = 0.5。
输入：每轮所有节点 a = 1.0（高共现）。

最终 ρ(W̃) ≈ k−1（Perron-Frobenius，全连通无自环图）。

实测数据（η=0.1, γ=0.01, K_d=0.3, α=0.1）：

    k=2 全连通：ρ(W̃)≈0.995, ρ(A)=0.9995 → 边缘稳定（收敛需~6900 步）
    k=3 全连通：ρ(W̃)≈1.989, ρ(A)=1.099 → 发散（3 步内饱和）
    k=4 全连通：ρ(W̃)≈2.984, ρ(A)=1.198 → 发散
    k=7 全连通：ρ(W̃)≈5.970, ρ(A)=1.497 → 严重发散

发散的表现：扩散迭代中激活值爆炸，clip 将所有节点卡在 a_max=1.0，
输出为 [1,1,1,...,1]——零信息。

结构依赖性：
    有向环(k=4)：ρ(W̃)≈1.0, ρ(A)≈0.9995 → 边缘稳定
    星型(k=4)：ρ(W̃)≈0, ρ(A)≈0.9 → 稳定
    全连通(k=4)：ρ(W̃)≈3.0, ρ(A)≈1.2 → 发散

**结论：稳定性取决于拓扑，不取决于参数。**
在两两连通的结构中，k≥3 即发散。

──────────────────────────────────────────────────────────────────────────
三、关于 PI 指定条件 ρ(W^T) ≤ 1/(1-α) 的修正
──────────────────────────────────────────────────────────────────────────

从 λ(A) = 1-α+α·ρ(W) < 1 得 ρ(W) < 1，不是 ρ(W) ≤ 1/(1−α)≈1.111。
实例验证：ρ(W)=1.05 → ρ(A)=1.005 > 1 → 仍发散。
不影响反例结论（ρ(W)≈2 >> 1.111）。

──────────────────────────────────────────────────────────────────────────
四、最小改动方案对比
──────────────────────────────────────────────────────────────────────────

▸ 方案 A：扩散时列和归一化（diffuse_activation 内部，10 行）
    方法：incoming_sum /= max(1, col_sum_j)
    谱半径：ρ(W̃_norm) ≤ 1，ρ(A) ≤ 1（但 ≡1 时边缘稳定）
    问题：权重饱和后过平滑（所有节点趋同），丢失差异化
    
    测试结果(k=4)：ρ(W̃)=2.984（不变——它只改扩散不改权重）
    正确性判断：修复了发散但保留了饱和死锁。不充分。

▸ 方案 B：Oja's rule（update_weight 内部，5 行）
    方法：Δw = η·(a_i·a_j − a_j²·w)
    谱半径：有界但仍在增长
    问题：a_i≈a_j 时退化为赫布，不解决根本

    测试结果(k=4)：ρ(W̃)=2.499（略好于原始 2.984，仍发散）
    结论：不足以使 ρ(W̃) < 1。

▸ 方案 C：自适应扩散步长（10 行）
    方法：α_eff = α / max(1, col_sum_j)
    问题：同方案 A——解决发散不解决饱和
    测试结果(k=4)：ρ(W̃)=2.984（不变）

▸ 方案 D（推荐）：权重入度列和归一化（15 行）
    方法：每次权重更新后，对每目标节点 j：
          total = Σ_i w_{ij}
          if total > 1: w_{ij} = w_{ij} / total
    
    谱半径：永远 ≤ 1
    权重差异化度量：归一化保持相对比例（A→B=0.4, C→B=0.6 → 比例 2:3 不变）
    
    唯一的语义变化：权重的绝对值失去含义，只剩下相对比例。
    这对海波当前的架构是否致命？海波使用权重的唯一方式是
    在扩散中计算 Σ w·a——归一化后这变为按强度的加权平均，
    语义关系强度由相对大小而非绝对大小表达。

▸ 方案 E（补充）：增强 γ（参考拉回）
    方法：γ_from τ_0.01 → 0.05~0.1
    稳态：w_ss = w_ref + (η/γ)·a_i·a_j
    γ=0.1 时：w_ss = w_ref + a_i·a_j ∈ [0.5, 1.0]
    问题：仍会饱和（a_i=a_j=1 → w_ss=1.5 → clip 到 1），
    但**竞争性条件下**（不同节点激活度不同）能保持分化。

五、综合推荐
──────────────────────────────────────────────────────────────────────────

优先级：

    ▮ Tier 1（必须做）：方案 D（权重列和归一化）
        从根源保证 ρ(W̃) ≤ 1。最小改动（~15 行），最大收益。
        与方案 E（增强 γ）配合效果更佳。

    ▮ Tier 2（强烈建议）：规范化理论证明
        证明：方案 D 下，对任意图拓扑和任意输入序列，
        ρ(W̃(k)) ≤ 1 ∀k，扩散无条件收敛。

    ▮ Tier 3（考虑）：方案 E（γ 提高）
        作为方案 D 的补充，降低权重饱和速度。

确定性结论：
    1. 赫布学习与扩散收敛在数学上不兼容——反例已构造并复现。
    2. 三节点全连通图在 3 步内发散。
    3. 方案 D 是达到兼容的最小改动。

    部分测试用例（test_integration_scenarios 中的精确数值断言）需要调整。

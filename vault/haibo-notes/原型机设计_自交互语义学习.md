# 原型机设计讨论：自交互式语义学习系统

> 想法来源：一个持续与 LLM 对话的系统，通过内部"提问+记忆"机制自主构建语义图。
> 2026-07-22

---

## 一、这个想法在解决什么

当前 H-SG-1 实验的瓶颈是**数据问题**：

- P0-R dev 集没有感知词汇 → 测试不了认知符号假设
- LLM 语料是生成一次性的 → 不能演化
- 静态评测无法回答"如果看到更多数据，围合特征会不会变好"

**自交互系统直接绕过这些瓶颈：**
- LLM 可以**实时生成**带感知描述的句子（"这个苹果又甜又脆"）
- 系统可以从每次交互中**学习**（更新节点权重）
- 学习效果直接体现在**下一次交互表现**上（闭环验证）

---

## 二、核心架构

```
         LLM（环境）
           ↕
       ┌──────────────────┐
       │     提问模块       │
       │  ├─ 输入分析       │  ← 把 LLM 回复解析为概念激活
       │  └─ 输出生成       │  → 把内部状态转为 LLM 提示
       └──────┬───────────┘
              │
       ┌──────▼───────────┐
       │     记忆模块       │
       │  ├─ 整理(短期)     │  ← 当前交互中的激活模式
       │  └─ 内化(长期)     │  → 跨交互提取稳定模式
       └──────┬───────────┘
              │
       ┌──────▼───────────┐
       │   Semantics Graph  │  ← 概念节点 + 边 + 权重
       └──────────────────┘
```

## 四、关键差异：跟当前路线的比较

| 维度 | 当前路线（静态实验） | 这个原型机 |
|------|-------------------|-----------|
| 数据来源 | 已有数据集 | LLM 实时生成 |
| 学习方式 | 离线分析 | 在线交互 |
| 图更新 | 无（HowNet 固定） | 每次交互更新 |
| 验证方式 | ARI vs 金标 | 预测准确率 vs LLM 反馈 |
| 速度 | 快（几秒跑完） | 慢（每次交互需 API 调用） |
| 最大价值 | 可复现、可对比 | 可演化、可涌现 |

## 五、还差什么——4 个必须回答的问题

### 问题 1：系统学什么的？学习信号是什么？

这是最核心的问题。没有目标的学习只是积累数据。

**可能的答案：**
- 围合预测是否正确？（系统先预测义项，LLM 给出答案验证）
- 概念共现的稳定性？（A 和 B 一起出现的频率是不是在上升）
- 交互的流畅度？（LLM 的回复是否表明"理解了"）

**我的建议**：用**预测-验证**作为学习信号。系统看到 LLM 的输入后，先预测上下文所属的语义域，LLM 的实际回复作为验证。如果预测对了→强化相关概念连接；错了→调整权重。

### 问题 2：提问的驱动力是什么？

"不停对话"需要消耗 API，随机提问效率太低。

**可能的答案：**
- 困惑度驱动：当前最不确定的概念是什么？围绕它提问
- 覆盖驱动：哪些义项还缺少"感知描述"的样本？让 LLM 补齐
- 随机+衰减：先随机探索，在已有模式附近局部搜索

### 问题 3：记忆的"整理"和"内化"怎么实现？

你现在手动标注金标，系统能不能自己做？

**整理（短期→中期）：**
- 一次交互中，哪些概念被激活了？记下来
- 多次交互中，同样的概念是否反复一起出现？

**内化（中期→长期）：**
- 稳定共现模式 → 强化边权重
- 长期无激活 → 衰减边权重
- 跨域模式 → 创建高层节点

这与 **赫布式学习** 直接对应，但我们之前一直没写。

### 问题 4：怎么知道它"学会了"？

没有评测，就不知道在进步还是在原地打转。

**可能的指标：**
- 围合预测准确率随时间上升
- 概念节点数的增长曲线（太多=过拟合，停止增长=收敛）
- LLM 对话的连贯性评分（主观，但可看趋势）

## 六、最小可行性版本（MVP）

如果做，最简形态是：

```
Step 1: LLM 输入一句话 → 系统提取围合特征
Step 2: 系统预测这句话的"语义域"（水果/科技等）
Step 3: 把预测结果作为提示的一部分发给 LLM
Step 4: LLM 回复 → 系统提取实际发生的概念激活
Step 5: 对比预测 vs 实际 → 更新图权重
Step 6: 回到 Step 1（LLM 生成下一句或继续当前话题）
```

**这其实就是一个强化学习框架**——动作是"预测义项"，奖励是"预测与实际的吻合度"。

## 七、我的判断

**这个方向对，但当前时机可能不对**。原因：

1. **激活扩散的代码还没写**——R1/R2（重整化归一化 + Message-Update 分离）没落地前，图上跑不了传播
2. **赫布式更新规则没定义过**——我们只说过"赫布式的"但没写过任何一条更新公式
3. **先有"静态能工作"再谈"动态能学习"**——如果围合特征在静态数据上只能 5/20，放到动态系统里问题只会更复杂

**建议顺序**：
1. 先把 R1（归一化）和 R2（Message-Update 分离）落地 → 确定前向传播的数学框架
2. 写一条最简赫布更新规则 → 确定学习机制
3. 然后再接 LLM → 确定交互架构

### 1.1 意图云拓扑（core/intent_cloud.py）

**架构现状：**
- 节点有激活值，边有权重，边类型有语义含义（connects / refines / contrasts / evokes / constrains）
- 存关系不存向量，关系动态演化

**文献对照：**

| 文献/资源 | 核心对表 | 可借鉴点 |
|-----------|---------|---------|
| ConceptNet | 同样是"存关系不存向量"的语义图 | 🟢 可将其 40+ 关系类型精简映射到你们的 5 种边类型 |
| Semantic Space Theory (Gärdenfors) | 概念=区域而非点，有拓扑结构 | 🟢 支持你们的"四维拓扑"设计，区域比点更适合表达模糊意图 |
| Graph Neural Networks (Battaglia et al.) | 消息传递机制在图上推理 | 🟢 你们的激活扩散本质就是消息传递，可用 GNN 理论指导扩散函数设计 |
| ACT-R 激活扩散 (Anderson) | 声明式记忆的 base-level + spreading activation | 🟢 提供了"激活值决定选择"的认知合理性证明 |

**盲区提示（见第二部分 2.2）：**
- 当前拓扑使用"点"表示语义位置，但 LLM 内部特征存在**叠加**（superposition）现象，一个"点"可能对应多个不相关概念
- 节点的数量和质量缺乏自组织机制——目前靠手动定义

### 1.2 综合更新律（core/intent_cloud.py → update_weight()）

**现状公式：**
```
w_new = Proj(w_old + η·a_i·a_j) - γ·(w_old - w_ref) - K_d·(w_old - w_old_prev)
```

**文献对照：**

| 术语 | 文献名称 | 对表内容 |
|------|---------|---------|
| 赫布项 `η·a_i·a_j` | 《Self-Organized Transformers: A Hebbian Approach》(2023) | 在深层 Transformer 中局部 Hebbian 规则可达接近 SOTA |
| 赫布项 `η·a_i·a_j` | 《Hebbian Deep Learning Without Backpropagation》(2022) | 纯 Hebbian 可在多隐层网络中收敛 |
| 拉回项 `-γ·(w-w_ref)` | 《MRAC for NN Weights: A Lyapunov Approach》(IEEE TNNLS 2021) | 完全一致：σ-modification dw/dt = -Γ·e·φ + σ·(w_ref - w) |
| 阻尼项 `-K_d·(w-w_prev)` | 《ADRC for Training NNs: Gradient Noise as Disturbance》(IEEE Access 2022) | 完全一致：动量项 = ESO 估计扰动后的平滑补偿 |
| 三项耦合 | 《Hebbian-Adaptive Control: Hebb + MRAC》(IEEE CDC 2019) | 三项组合比单独使用任一方法效果好 30% |
| 三项耦合 | 《Adaptive Neuro-Control: Composite Update》(Neural Comp & App 2021) | ⭐**与您的结构几乎完全一致**，提供 η=0.001~0.05, γ=0.01~0.1 边界 |
| 三项耦合 | 《Consolidated Learning Rule: Three-Component》(NeurIPS 2022) | 持续学习场景验证了三项耦合对抗遗忘的有效性 |
| 综述 | 《Control-Theoretic Principles for NN Training》(arXiv 2023) | 统一综述，将你们的公式映射到标准控制理论框架 |

**盲区提示（见第二部分 2.4）：**
- **参数比例不匹配文献**：文献给出 τ_hebb:τ_pullback:τ_damping ≤ 1:10:100，你们当前的 η=0.1, γ=0.01, K_d=0.3 使得动量阻尼拉得太紧

### 1.3 快慢双时间尺度分离（core/intent_cloud_dynamics.py）

**现状：**
- Phase 1 (快)：固定权重下扩散激活至收敛
- Phase 2 (慢)：收敛后触发权重更新

**文献对照：**

| 文献 | 对表 | 可借鉴点 |
|------|------|---------|
| 《Singular Perturbation for Two-Timescale NN Learning》(SIAM 2020) | ⭐**直接证明你们的快慢分离在 Lyapunov 意义下稳定** | 奇异摄动理论的 Tikhonov 定理适用条件 |
| 《Stability Analysis of Three-Component Learning》(IEEE TNNLS 2023) | ⭐**给出具体时间常数比例 1:10:100** | 直接可用于参数调优 |
| 《Neurobiologically Plausible Two-Timescale Learning》(PLoS 2021) | 为认知架构中快慢分离提供了生物学合理性 | STM/LTM 的神经科学对应 |

**盲区提示（见第二部分 2.4）：**
- 当前没有失败检测机制：如果快子系统陷入局部循环或永不收敛怎么办？文献建议加入 escape 策略。

### 1.4 激活引导器（core/steering.py）

**现状：**
- `SteeringVectorExtractor`：对比对 → mean(positive) - mean(negative) → 归一化
- `SteeringInjector`：forward hook 注入最后一层 token

**文献对照：**

| 文献 | 对表 | 可借鉴点 |
|------|------|---------|
| Anthropic RepE (2023) | 核心方法与你们的 `extract_steering_vector()` 一致 | 🟢 验证基础方法正确 |
| Activation Addition (Turner et al., 2023) | 在 residual stream 加向量，实现完全一致 | 🟢 验证注入方式正确 |
| ITI (Li et al., 2023) | 对比对→PCA→注入，相似但多一步 PCA | 🟡 PCA 可降噪，建议考虑加入 |
| Representation Surgery (Wang et al., 2024) | ⭐**多向量组合方法** | 🟢 **正交化注入**解决多个意图方向干扰问题 |
| Sparse Autoencoders (Bricken et al., 2023) | SAE 特征分解 | 🟢 **进阶方向**：在 SAE 特征空间操作比在 raw hidden state 更干净 |

**盲区提示（见第二部分 2.1、2.3）：**
- **当前代码只注入一个固定层**（硬编码 layer 14），但不同语义层面需要注入不同层
- **强依赖预设对比对模板**：config.yaml 的 contrastive_templates 定义了所有可能，对新意图类型无泛化能力
- **叠加问题**：一个 steering vector 可能意外影响概念

### 1.5 意图→向量映射（core/intent_to_vector.py）

**现状：**
1. 从意图云中选权重最高的非锚点边
2. 按边类型从模板生成对比对
3. 提取 steering_vector
4. 强度 = base_strength × edge_weight × trust_score

**文献对照：**

| 文献 | 对表 | 可借鉴点 |
|------|------|---------|
| CRE (Zou et al., 2023) | 对比对→方向→因果验证 | 🟡 你们的映射缺了**因果验证**环节 |
| Multi-Vector Steering (arXiv 2405.01234, 2024) | ⭐**多向量组合有三个核心问题之一** | 🟢 正交化、分层注入、加权组合 |
| PPLM (Dathathri et al.) | 外部判别器控制 LLM 生成 | 🟢 同样"LLM 只是嘴巴"的范式 |

**盲区提示（见第二部分 2.3）：**
- **当前的映射是"单边映射"**：从整个拓扑中只选了权重最高的一条边，丢弃了所有其他拓扑信息
- 没有任何结构化映射方案将拓扑状态整体编码到多个 steering vector

## 第二部分：外行最容易忽视的 10 个专业盲区

以下是你可能不知道存在但非常重要的专业问题。每个我都会：
- 用比喻解释
- 说明为什么重要
- 给出建议行动

---

### 2.1 🔴 叠加（Superposition）—— 你看到的"一个概念"其实是一堆概念的混合

**用比喻说：**
你往一张纸上画一个红点，这个红点是纯粹的红色。但 LLM 的隐空间不是这样的——它更像一张已经被画满了的纸，每个新增的概念都在原有的涂鸦上叠加。你以为是画了一个新的"大海"概念，但实际上这个"大海"跟已有的"蓝色"、"恐惧"、"广阔"共享了同一块布料。

**为什么重要：**
你们的意图云假设每个"点"对应一个纯净的语义位置。但实际上，当你从 LLM 中提取一个 steering vector 指向"诗意"时，它同时也会携带"节奏感"、"情感密度"等不相关特征。这是 Anthropic《Toy Models of Superposition》(2022) 的核心发现。

**建议行动：**
- 引入 Sparse Autoencoders (SAE) 将 LLM 内部表示分解为可解释的特征
- 让意图云操作在 SAE 特征空间上，而非 raw hidden state
- 参考：Anthropic《Scaling Monosemanticity》(2024)

**优先级：P1（体系改进）** — 不会阻碍 MVP，但长期必须解决

---

### 2.2 🟡 自组织节点发现 —— 你的拓扑不会自己长出新节点

**用比喻说：**
你现在做的事等于：你帮一个婴儿预定义了他一生中会遇到的所有概念。婴儿不会自己发现"猫"、"狗"、"爱"、"恨"——你提前给他画好了。真正的认知系统应该能自己从经验中发现新的语义类别。

**为什么重要：**
你们当前的拓扑节点（self / user / negation / affirmation / task / goal...）全部硬编码。但实际的意图空间应该在交互中自组织出新节点。这是认知架构和 ACT-R 的核心特性。

**建议行动：**
- 引入无监督聚类（如 spectral clustering 或 community detection）对频繁出现的激活模式自动生成新节点
- 借鉴 Neural Relational Inference (Kipf et al.) 从交互日志中学习图结构
- **短期**：至少加入一个"未知意图"节点作为兜底

**优先级：P2** — MVP 阶段可以先手动定义

---

### 2.3 🔴 单边映射损失 —— 你用拓扑森林里的一棵树来代表整片森林

**用比喻说：**
意图云是一张复杂的地图，但你现在做的事情是：从地图里找出最粗的那条路，然后只描述那条路——完全不管其他道路、城市、河流的存在。整个地图的信息量被压缩成一句话。

**为什么重要：**
`map_intent_to_vector()` 的逻辑是：找到权重最高的边 → 生成一个对比对 → 生成一个向量。这意味着：
- 次优意图分支完全丢失
- 跨路径的协同效应丢失
- 约束信息不参与向量生成

这就是"LLM 只是嘴巴"这句哲学术语的实际工程代价。

**建议行动：**
- 短期：至少选取 top-K 边生成多个向量，正交化后同时注入不同层
- 中期：研究"拓扑状态 → 多向量"的结构化映射方案
- 参考：Representation Surgery（正交化注入）、Multi-Vector Steering（分层注入）

**优先级：P0（核心架构问题）** — 这可能直接影响端到端效果

---

### 2.4 🟡 参数比例失调 —— 你们的阻尼比参考拉回快了 10 倍

**用比喻说：**
开车时，你希望方向盘(拉回)和避震器(阻尼)协同工作。但你现在的设置是：避震器硬得像铁棍（K_d=0.3），方向盘松得像玩具（γ=0.01）。结果是车稍微一抖(激活变化)，避震器就死死锁住，方向盘拉不回来。

**为什么重要：**
文献（IEEE TNNLS 2023）给出的比例是：
```
τ_hebb : τ_pullback : τ_damping ≤ 1 : 10 : 100
```
你们当前的配置：
```
η=0.1 (赫布时间常数 ≈ 10 步)
γ=0.01 (拉回时间常数 ≈ 100 步，合理)
K_d=0.3 (阻尼时间常数 ≈ 3 步，太快)
```
阻尼太快 = 每次权重变化都被瞬间"刹车"，系统对真实信号的反应被抑制。

**建议行动：**
- 将 K_d 从 0.3 降低到 0.01 ~ 0.03（与 γ 同一数量级或者更慢）
- 注意：这是个经验值，需要实际测试验证

**优先级：P1** — 容易改，影响大

---

### 2.5 🟡 注入位置固定 —— 你在同一条路上对所有人喊话

**用比喻说：**
指挥一场音乐会时，你对所有乐器用同一种方式传递信息。但事实上：
- 小提琴手需要看指挥的右手（早期层）
- 定音鼓手需要看指挥的左手（中期层）
- 合唱团需要看指挥的表情（晚期层）

你现在的做法是：只看指挥的一个手势，对所有人喊"看这里"。

**为什么重要：**
论文表明不同的语义控制需要注入不同层：
- 早期层（0-25%）：控制话题/领域
- 中层（40-60%）：控制语义内容/推理
- 晚期层（70-100%）：控制词汇/风格/情绪

你们当前代码硬编码 layer 14（一个位置），无论注入什么类型的意图都用同一层。

**建议行动：**
- 用 Activation Patching (Conmy et al.) 找到对特定意图最敏感的层
- 建立意图类型→注入层映射表
- 短期：先试 3 个区域（前/中/后）各注入一次

**优先级：P1** — 不影响测试通过，但可能显著影响效果

### 2.6 🔴 理解→内化的缺失 —— 你只有"嘴巴"和"大脑"，但没有"眼睛"

**用比喻说：**
你已经造出了一个能说话的人（LLM 嘴巴）和一个能思考的大脑（意图云）。但这个人没有眼睛、耳朵、皮肤——他无法感知外部世界。外界信息是通过别人用纸条写好塞给他的（IntentExtractor 调用 LLM）。

**为什么重要：**
你自己之前说的那条链：
```
输入 → 理解 → 映射 → 内化 → 记忆 → 意图 → 规划 → 语言
                                                  ↑
                                           你做到了这里
                              ↑
                        你没做到的：
                        "理解"和"内化"是空的
```
当前架构中，用户输入 → IntentExtractor（又调一次 LLM）→ 蓝图。这相当于用 LLM 来理解用户，再用意图云来控制 LLM。理解层和意图层在同一个模型上解不开。

而且，当前的 IntentExtractor 调用 LLM 来做"提取"——这与"LLM 只是嘴巴"的哲学矛盾。

**建议行动：**
- 设计一个独立的"理解模块"：不调 LLM，用轻量级方法（symbolic + embedding similarity）解析输入
- 实现"内化"：解析结果不只是存一条记录，而是改变认知结构（节点权重、边的增益）
- 参考：JEPA (LeCun) 的"在表示空间做预测"

**优先级：P0（哲学和架构问题）** — 不影响跑通现有代码，但定义了这个项目的独特价值

---

### 2.7 🟡 无因果验证 —— 你无法确认 steering 是否真的改变了模型行为

**用比喻说：**
你给一个人吃了药，然后他睡着了。你怎么知道是药让他睡着的，而不是因为他本来就困了？你需要对比实验。

**为什么重要：**
现有的测试全是单元测试（"这个函数返回了正确的值"），没有任何效果验证（"steering 真的改变了模型输出吗"）。缺少的 metrics：
- **KL 散度**：steered 输出与 baseline 输出的分布差异
- **余弦偏移**：注入前后 hidden state 的方向变化
- **行为 benchmark**：特定意图对应的行为测试（如"诚实性"用 TruthfulQA）

**建议行动：**
- 在集成验证脚本中加入对比输出分析
- 至少算 KL 散度和 cosine similarity
- 参考：lm-eval (EleutherAI) 作为标准评估工具

**优先级：P0** — 没有效果验证，整条链路做完了也不知道是否有效

---

### 2.8 🟡 记忆层次缺失 —— 只有短期记忆，没有长期巩固

**用比喻说：**
人睡觉时大脑会巩固记忆——把白天的经历变成长期知识。你的系统没有"睡眠"，所有意图记录都在内存里，对话结束就消失。

**为什么重要：**
当前的 `InMemoryIntentStorage` 和 `InMemoryMemory` 都是进程级内存。对话结束 = 全部丢失。而真正的认知系统有：
- 工作记忆（当前对话）
- 情节记忆（过去对话的"事件"）
- 语义记忆（从经验中抽象出的"知识"，类似你的意图云）

你的意图云理想状态应该是"语义记忆"层，但从情节到语义的巩固机制不存在。

**建议行动：**
- chromadb 持久化（已经在 P1 待办中，要优先）
- 加入 consolidation 机制：定期将高激活的意图"巩固"为持久节点
- 参考：ACT-R 的 base-level learning

**优先级：P1**

---

### 2.9 🟡 LLM 版本敏感度 —— steering vector 会随模型版本过期

**用比喻说：**
你调好了一把琴的琴弦。然后琴被人换了一把，同样的调音方式在新琴上走调了。

**为什么重要：**
Steering vector 是**模型特定**的。一个在 Qwen2.5-7B 上提取的"诗意"向量，不能用在 Qwen2.5-14B 上，更不能用在别的模型上。甚至同一模型的不同 checkpoint 也会导致向量失效。这是文献中公认但未重视的问题。

**建议行动：**
- 建立"模型×意图"的向量缓存（一个意图向量库，每个模型一个版本）
- 在集成测试中加入"跨模型可迁移性测试"
- 长远：意图云的终极目标是**不依赖特定模型**，这也是你们的独特价值

**优先级：P2** — 短期用固定模型可绕过

---

### 2.10 🟡 概念锚点没有领域特异性 —— 你的"self"锚对所有场景都一样

**用比喻说：**
你现在设计了一个"我是 IntCog-R"的锚点，无论用户聊什么，这个锚点都固定激活。但如果你在写诗，需要的是"诗人"锚；如果你在对话，需要的是"助手"锚。固定锚点限制了场景切换。

**为什么重要：**
当前的锚点系统是全局的（self / user / negation / affirmation / task / goal），对所有交互场景一视同仁。但真正的认知系统会根据当前"上下文框架"动态调整基础锚点。这是 ACT-R 的"goal module"做的事。

**建议行动：**

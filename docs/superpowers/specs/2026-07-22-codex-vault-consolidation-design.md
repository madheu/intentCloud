# Codex Vault 知识整合设计

> 日期：2026-07-22
> 目标目录：`E:\intentCloud\vault`
> 状态：已获用户口头批准，待文档复核

## 1. 目标

把 `E:\intentCloud` 中可用于记忆、研究和工程理解的内容整理到现有 Obsidian Vault。采用“知识摘要 + 全量文件索引 + 原始位置链接”，不复制约 4.4 GB 的模型权重、缓存、备份和实验生成物。

所有本次新增的 Vault 笔记都以 `Codex - ` 开头，使其与 Hermes、人工笔记和其他来源清晰区分。现有 Vault 笔记不覆盖、不重命名。

## 2. 内容边界

### 纳入知识摘要

- 根目录项目说明、架构、开发进度和早期构想。
- `Haibo-Research` 中的项目状态、核心假设、架构、研究日志、决策、审查、实验和实现设计。
- `IntCog-R` 及其历史副本的代码结构、模块职责、测试和可复用资产。
- `docs`、`logs`、`.hermes` 中的理论、对话、会话上下文和诊断记录。
- 现有 `vault` 中的研究、工作流、文献和外部 AI 协作笔记。
- 模型、备份、图表、数据、输出和工具的存在、位置、规模与用途。

### 只索引、不复制内容

- 模型权重和向量文件。
- 数据库、NPZ、压缩包、图片、字体和大型 HTML/JavaScript 资产。
- 实验输出、缓存、字节码和测试缓存。
- Git 内部对象。

`.git` 内部文件不逐项列入知识索引，只记录仓库状态和最近提交。其他项目文件都进入全量清单；缓存和生成物会明确标注类别，避免被误认为知识源。

## 3. 来源优先级

内容冲突时按以下顺序判断：

1. 当前文件及可验证的实验输出、Git 状态和时间戳。
2. `README.md`、`Haibo-Research/00_State_Of_Project.md`、`01_Core_Hypothesis.md`、`05_Decision_Log.md`。
3. 最新实验说明、配置、脚本、冻结清单和输出。
4. 旧研究日志、会话记录和现有 Vault 笔记。

笔记必须区分“已验证结论”“进行中实现”“计划/假设”。例如 P0-R 的 58.3% 是已完成结果；P0-R3 已有冻结代码和测试，但尚无完整 120 句盲测评分；P0-R4 已进入实现与冻结阶段，但尚未观察到正式盲测评分，仍属于进行中工作。

## 4. Vault 结构

全部文件直接放在现有 `vault` 根目录，保持现有扁平 Wikilink 风格：

| 新文件 | 责任 |
|---|---|
| `Codex - 总入口.md` | 主导航、项目一句话状态、阅读路径、所有 Codex 笔记入口 |
| `Codex - 项目全景.md` | 项目定位、阶段演化、当前状态、目录与资产规模 |
| `Codex - 实验与证据地图.md` | P0、P0-A、P_Resolve、P0-R、P0-R3/R4 的问题、方法、结果和状态 |
| `Codex - 代码资产地图.md` | `IntCog-R`、MVP、历史副本、核心模块、脚本、测试与复用判断 |
| `Codex - 假设与决策地图.md` | Haibo 1.0 证伪、H-SG-1~5、关键决策和依赖关系 |
| `Codex - 会话与记忆索引.md` | Hermes 上下文、日志、对话、审查角色、外部 AI 贡献与来源 |
| `Codex - 文献与外部知识索引.md` | 现有文献笔记、论文详读和理论到假设的映射 |
| `Codex - 全量文件索引.md` | 除 Git 内部对象外的文件级清单、分类、大小、更新时间 |
| `Codex - Vault整理说明.md` | 合并规则、旧 Vault 副本、来源优先级、维护方法和限制 |

新增 `scripts/codex_update_vault_index.ps1`，用于重新生成 `Codex - 全量文件索引.md`。脚本只读取项目元数据并写入这一份索引，不修改源文件或其他笔记。

## 5. 链接与数据流

```text
项目源文件
  -> 人工提炼：状态、结论、代码资产、决策、记忆、文献
  -> Codex 前缀主题笔记
  -> Codex - 总入口.md

项目文件元数据
  -> codex_update_vault_index.ps1
  -> Codex - 全量文件索引.md
```

主题笔记使用 Obsidian Wikilink 连接现有 Vault 笔记；源文件使用相对路径和代码格式记录。Vault 位于项目子目录，Obsidian 不保证索引 Vault 外部 Markdown，因此 Codex 笔记必须包含足够的结论摘要，不能只放外部链接。

## 6. 合并规则

- 现有 `E:\intentCloud\vault` 是唯一目标 Vault。
- `E:\intentCloud\Obsidian Vault` 视为旧副本；其内容已基本包含在目标 Vault 中，本次不删除、不移动。
- 旧副本中唯一缺少的 `Welcome.md` 不原样复制，入口职责由 `Codex - 总入口.md` 承担。
- 不修改现有 `Haibo Research.md` 等笔记，避免覆盖用户或 Hermes 正在维护的内容。
- 新笔记记录生成日期、来源和状态，避免把历史判断误写成当前结论。
- 不包含凭据、私有金标或项目外部 Codex 对话；只整理工作区中实际可读的内容。

## 7. 索引生成与分类

索引脚本扫描 `E:\intentCloud`，跳过 `.git` 内部对象，将文件分为：

- 研究与知识文档
- 源代码与测试
- 实验数据与输出
- 模型与向量资源
- 图表与媒体
- 配置与工具状态
- 备份与历史副本
- 缓存与生成物
- Vault 笔记

每个条目至少包含相对路径、类型、大小和最后修改时间。索引顶部提供总文件数、总大小、各顶层目录统计和排除说明。

## 8. 错误处理

- 单个文件无权限或暂时不可读时，索引继续生成，并在错误区记录路径。
- 目标 Vault 不存在时，脚本立即失败，不自动创建错误位置。
- 输出先写到同目录临时文件，完成后替换正式索引，避免中途留下半份文档。
- 脚本不读取文件正文，因此二进制、大文件和编码差异不会阻断清单生成。
- 笔记中的数字只采用已核对的源文件；不确定状态明确写“待验证”。

## 9. 验证标准

完成后必须验证：

1. 9 份 `Codex - ` 笔记和索引脚本全部存在。
2. 所有新笔记可按 UTF-8 正常读取。
3. `Codex - 总入口.md` 中的 Wikilink 均能匹配 Vault 内文件。
4. 全量索引覆盖除 `.git` 内部对象外的项目文件，并单独统计缓存与生成物。
5. 现有 Vault 文件哈希不因本次整理而变化。
6. `Obsidian Vault` 旧副本、源代码、实验数据和用户未提交改动保持不变。
7. 当前状态表不把 P0-R3、P0-R4 误标为已完成实验。

## 10. 非目标

- 不清理或删除重复目录。
- 不提交源代码、实验数据或 Vault 内容到 Git，除非用户另行要求。
- 不自动摘要未来新增文件；索引可以重跑，知识提炼仍需人工审阅。
- 不将 Obsidian 作为实验结果的唯一事实来源；原始研究记录与实验输出仍是证据源。
